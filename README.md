A public source repository for a private, noncommercial digital prototype of the board game **Guards of Atlantis II** (2nd printing), built in Unity.

The project owner states that the public repository and included rulebook are shared with the relevant permission. Builds and excluded reference material are not public releases. See [Rights and distribution](#rights-and-distribution).

## What this is

A rules-accurate implementation of the board game, built as a pure C# rules engine with Unity acting only as passive presentation. The current build sets up the rulebook's official six-player match on the official single-lane map - three heroes a side, each dealt their own typed printed-card definitions - with movement, attack/defense, minions, and an end-of-round minion battle. Each card's printed text is composed slice by slice, and a primary action whose text is not composed yet is offered greyed and refused rather than performed without it.

Progress is tracked as numbered micro-milestones. The newest is **8.35z53**: Whisper the Outcast joins the roster as the eleventh playable hero, and she is the first whose cards put a decision in the OTHER player's hands - one of her attacks lets the hero who defended choose where their own card then drags them, and one of her skills offers the enemy the choice of which bad thing happens to them. Much of her kit only wakes up once somebody has spent a card, because it reads the discard pile. When the game is waiting for everyone to commit a card, EVERY card in your hand now breathes - before, only some did, and the reason was a shared budget of eight glowing things written back when a match had one hero tray instead of six, so the six trays used it up before your own cards were reached. The history tray has stopped printing board coordinates at you; it says "moved 3 spaces" now, or just "fast traveled", because a pair of numbers means nothing to a person. And the big one: a card that offered you a button which did nothing. Picking a space, pressing DONE, and watching your hero not move had been chased across eight separate test runs as a clicking problem, and it was not - an optional "make someone discard a card" step that ended up naming NOBODY was throwing an error instead of quietly doing nothing, and that error threw away the whole move and put the board back exactly as it was. Same screen, nothing moved, no complaint: indistinguishable from a dead button. It now does nothing quietly, as it always should have, and the two tests that had been parked on it are running again. It rests on **8.35z50**: a tenth hero you can pick and play - Ursafar the Savage, whose whole set turns on one idea. Most of his cards say "if enraged" and then do something extra, and almost all of them make him enraged afterwards, so the deck builds on itself over a match. Two things about him had never existed in this game before. One is a card that lets you perform the printed action of a DIFFERENT card of yours - not a copy of it, the real thing, with that card's own numbers and its own text - and the game now starts that borrowed action through exactly the same door a normal action goes through, so everything that is true of a normal action is true of a borrowed one without anything being copied. The other is a card that asks whether the target of the attack you just made is still standing, and only then removes something else; nothing in the game had ever recorded that before. He also came with a real find that had nothing to do with him: Silverarrow, added a few milestones ago, had been fully built and quietly impossible to pick, because the one place a new hero has to be listed lives in a comment rather than in a check. She is pickable now, and there is a check, so the next hero that forgets cannot get past it. It rests on **8.35z49**: two cards that could never be played, and a checklist that had been reading half of some cards. A few cards print instructions at two separate moments of an attack - something before it, something after - and the tool that checks "can a player actually reach everything this card says?" had only ever read the first half. It reads both now. Across every card in the game that turns out to be five cards, and only two of them belong to a hero anyone can currently play, so the honest size of the change was measured rather than guessed: those two now correctly claim the after-the-attack moment they always had, and every other card's answer is unchanged, letter for letter. The second fix is a real one a player would have hit. Two cards say, in effect, "if you are angry, you may step somewhere first; then pick who you are hitting." The game checks in advance whether an attack can possibly find a target, so it never offers you something that cannot work - and that check treated "if" the same way it treats "choose one", concluding that because the optional step contained no target, the whole card was hopeless. But the target was not inside the "if" at all; it was written on the line after it. Both cards would have been greyed out on every board, always. A sweep of all 177 composed cards confirms those two are the only ones with that shape, and a deliberate counter-test keeps the "choose one" behaviour, which is genuinely different, from being changed by accident. It rests on **8.35z48**: a click on the board is answered by the board. A hero's piece is picked by an invisible ball around it that is nearly as wide as a space, and the game asked, in order, "is this hero an answer to what I am asking, and if not, does clicking a hero at least mean show me that hero's cards?" - and that second question almost always says yes. So a click aimed past a piece at a space was swallowed by the piece: the game reported success, and nothing moved. It now asks every question that can actually change something - this hero, this small figure, this space - before it falls back to simply pointing the tray at a hero, which is what the code's own comment had said it did since the day it was written. Clicking a hero to read their cards is untouched; a click that genuinely does nothing now says so instead of claiming it worked. The hunt also finally pinned a separate puzzle that had cost eight test runs and looked identical from the outside: one hero's placement finished on one setup and did nothing on another. That one is not a swallowed click at all - the click arrives and is accepted, the board narrows to the space you picked, and then the DONE button the game offers you does nothing when you press it, however many times you press it. That is a different fault, in the rules layer rather than in the clicking, and it is now written down with a one-minute way to reproduce it instead of an eight-run mystery. It rests on **8.35z47**, two things the user found by playing the build: the light that means "the game is waiting on you" never appeared to breathe, and the history panel that drops from the top bar was a different colour from the bar. The light turned out to be right all along - the right colour, the right curve, the right two-and-a-bit-times swing, ticking every frame - and painted onto an edge one pixel wide at the size the screen is designed for, which is half a pixel on a normal monitor. Nothing about the timing changed; the light was simply given a band wide enough to be a light. The panel now takes its colour from the bar itself rather than keeping its own copy, so the two cannot drift apart again. It rests on **8.35z46**, where the third of the six newer heroes is dealt into the game. Silverarrow the Pathfinder can be picked up and played - her cards are in a hand, her piece is on the board wearing her own artwork, and everything she does has been driven through the real screen by a test that clicks what a player clicks. Her deck plays a war of attrition through forced discards rather than raw damage, and one of her cards, Rain of Arrows, prints three steps in a row: hit somebody at long range, and if that somebody was a hero, hit a second, different hero the same way, and if THAT one landed too, hit one of the enemy's small figures on top. The second of those three steps had been built already; the third had not, and writing it turned up something the earlier work had not seen coming. The game already has a rule that stops a card repeating an attack it has already repeated once - printed on page 10 as "you cannot repeat a repeated action" - and that rule could not tell the difference between "you already used this exact repeat" and "you are now trying a completely different repeat printed further down the same card". Left alone, it would have silently swallowed the third step every single time, so the card would have looked finished while quietly doing two-thirds of what it prints. The fix teaches the game to count which step of a card's own printed order it is currently on, using a piece of bookkeeping the game already keeps for an unrelated reason, so no saved game changes shape at all. Proven on a test board: the same card offers three targets in a row, each one narrower than the last, in exactly the order it prints them. And a quiet piece of housekeeping her dealing forced, the same shape found when Misa was dealt: her own hero token artwork had never actually been generated, and a check written for exactly that possibility caught it before a player would have. Before it, **8.35z45**: the last of Dodger the Warlock's cards that the game could not yet read is now built. Middlefinger of Death offers you two attacks and lets you take one or both, and the second one is picky about who it can hit - "a hero in range who has one or more cards in their discard pile". Nothing in the game could express "who", as opposed to "how far away" or "which kind of unit", so the card had been waiting through two earlier attempts to find the right place to put that idea. It now sits on the individual bullet of the card rather than on the general targeting rules every attack in the game shares - which matters, because changing the shared rules would have counted as changing every hero's cards, and none of theirs say anything of the sort. The proof is a single board position: on it, the card's first attack offers the enemy standing next to you while its second offers nobody at all, at the same instant - so the reach clearly works, and the only thing that can be turning the second one down is the new condition. One consequence for anyone with saved games: this changes the format saved matches are written in, so saves from the previous build are refused rather than half-read. That refusal is deliberate. An older save that happens to contain one of these multi-attack cards is SHORTER by one number per bullet, and a newer game reading it would start taking the next piece of the card out of the middle of the previous one - which is not a save that fails to load, it is a save that loads into nonsense. Before it, **8.35z44**: a tidy-up before the big build, in three parts. Fifty-five comments in the code named a milestone number that was never actually issued - a placeholder written while the work was still on a side branch, which nobody went back and filled in. They now name the milestones the work really landed under. Five of them were nearly filed under the wrong one, and the reason is worth knowing: the tool that tells you who last touched a line tells you who WROTE the comment, not who the comment is TALKING ABOUT, and several of these comments talk about a different milestone mid-sentence. Three more were deliberately left alone, because in those three the fake number is the point being made - they explain why a card's version was reset rather than bumped, and renaming them would make them say something false. Second, the little tool every worker uses to check the code still compiles was being privately copied around, and the copy everyone called "the shared one" no longer worked; it now lives in the project itself, which is also what fixes it - a copied file was quietly checking the wrong folder and telling people their work was fine. Third, one of Sabina's cards claimed a restriction that is not printed on it: her "move a friendly minion, then do it again" cards were declared as though the repeat had to pick a DIFFERENT minion. No such words appear on any of the three cards that shared that declaration, so it is gone. It never actually did anything - that was measured rather than assumed - but a rule the cards do not print has no business being in the game. Before it, **8.35z43**: when the game refuses to load a saved position, it now genuinely leaves the match exactly as it was. It used to try to put the old position back by reading it in again from a stored copy - which is the one thing you cannot rely on at that moment, because a refused load is precisely the situation where the game is having trouble reading things. If that second read also failed, the error escaped, and the match was left half-swapped: neither the old position nor the new one. The fix turned out to need nothing new. Loading a position REPLACES the game's internal state rather than editing it, so the old state is still sitting there intact and putting it back is just handing it over again - no reading required, and nothing that can fail. The same two lines fix undo and restart, which had exactly the same weakness. Alongside it: a practice player asked to play a seat that is not theirs now says no; a hero-selection screen that finishes with nothing to build the match refuses loudly instead of quietly building nothing; and a note left in the code claiming a network problem existed turned out to be wrong - the problem had been fixed years of milestones ago and only the tests were missing, so the tests were written and the wrong note corrected. The practice players' scoring was also re-measured across forty matches per setting and deliberately left alone, because nothing in it turned out to be worth changing. Before it, **8.35z42**: two of Tigerclaw's attack cards stop being offered when there is nobody he could possibly reach. Both of them let him take a step and then hit somebody standing next to where he ended up - so whether the attack is possible at all depends on where that step could take him, and the game had never worked that out. It offered the card whenever he held it, let you spend it, and only then discovered there was nobody to hit. Now it tries every square the step could reach, plus standing still where the card allows that, and greys the card out only when none of them puts an enemy in reach - and when it does grey it out, it now says which rule is stopping you, which this particular kind of attack could never do before. The change was measured rather than trusted: across eighteen different board positions and eighty-nine offers, exactly two changed, and both were the hopeless case. One card belonging to a hero who is not dealt into the game yet turns out to be greyed out everywhere for a related reason; that is written down for the milestone that deals her rather than guessed at here. Before it, **8.35z41**: every hero the game can actually deal is now offered in the lobby. Two heroes had been fully built, tested and playable for a while and still could not be picked, because the picking screen was reading the printed six-hero line-up instead of the list of heroes the game knows how to deal - so the roster now reads the right list, and picking one of the newer heroes really deals their cards. Before it, **8.35z40** made the match log unroll out of the top bar instead of dropping a differently-coloured box underneath it, put the newest thing that happened at the top (with the round and turn headings rearranging to match), and stopped the game announcing that your connection is fine - it now says something only when it is NOT fine. And **8.35z39**: the things the game highlights stopped being flat colour and became light. An awaited card or hero panel now breathes - its own gold edge dims and swells on a slow loop, instead of a little dot crawling around the outside - and a marked space on the map is lit up in its own colour rather than painted over, so the board artwork underneath still shows through. Nothing moved: every mark keeps the exact shape, size and colour it had, and only what the pixels inside it do has changed. Before it, **8.35z38** dealt the second of those six heroes into a game. Misa the Samurai can be picked up and played - her cards are in a hand, her piece is on the board wearing her own artwork, and everything she does has been driven through the real screen by a test that clicks what a player clicks. Her whole deck turns on one idea the game had never had to handle: distance as an exact number rather than as a limit. Where every other hero reaches "up to" so far, half of hers reach EXACTLY that far - a space precisely four away, two figures standing precisely three away, a shot that only pays off if its victim was at the very edge of range. That has a consequence worth stating plainly: her cards can be offered a choice with no legal answer, which for everybody else is nearly impossible, so the game has to grey those out and say why rather than accept them and waste the card. Her ultimate is the only one in the game that changes the SHAPE of a question instead of a fact about the board: a card reading "choose one" becomes "choose both, in either order". And a quiet piece of housekeeping the dealing forced: one rule is shared between her and a hero not yet dealt, so registering it for her retired the other hero's claim to it - which is the gate working, not a slip. Before it, **8.35z36** and **8.35z37** together let the lobby decide what game you actually sit down to play. Until now the board was built the instant the program started, before anybody had joined - so the heroes and the setup were fixed before a lobby existed, and any picking screen would have been a lie. The match is now built twice: a provisional one at startup, so people can join at all, and then the real one from what the lobby decided, at the moment the game starts. Nothing changes for a table that picks nothing - the provisional board and the chosen board are identical down to the byte, which is checked rather than assumed. On top of that seam: the host chooses the printed setup - three a side or two, short or long - on the join screen, and the board rebuilds under it; and the six players pick their heroes in the order the rulebook prints, alternating between teams starting with whichever team the Tie Breaker coin shows, with a hero somebody has already taken staying visible but greyed and saying why. A hero's colour is no longer baked into its picture either, so a hero can now play for either team without needing a second set of artwork drawn for it. Before them, **8.35z35**: when a card offers you a choice of two things to do, you can now pick the one that would achieve nothing, instead of finding it greyed out. That sounds small and it is not, because some cards hand the choice to your opponent - "an enemy hero in range chooses one" - and the entire point of those cards is that the enemy gets to take the cheaper way out. Where the cheap option was "discard a card if you are able" and that player held no cards, the game used to grey it out and force them onto the expensive one. Worse: where every option on a card would achieve nothing, the game stopped the card dead on the spot, so a later line of printed text on that same card never ran at all. Now the empty option is offered, taking it simply does nothing, and the rest of the card carries on. An option you genuinely cannot take - one whose required step is impossible - is still greyed out, and still names the hero and the card that is stopping you, exactly as before. Four options across the roster change; six other families of card do not move at all; and the one card this rule was originally measured on turns out to be unaffected, because both of its modes are the impossible kind rather than the empty kind. Before it, **8.35z34**: the first of those six heroes is now actually dealt into a game. Dodger the Warlock can be picked up and played - her cards are in a hand, her piece is on the board wearing her own artwork, and everything she does has been driven through the real screen by a test that clicks what a player clicks. Her whole deck turns on one idea: she is paid for the board emptying out. Her shields harden as minions die, her rituals earn coins from the gaps they leave, and two of her cards put a minion back. The last of those was where the interesting work was. The user had ruled that once her ultimate is up she can bring a minion back anywhere in reach - but the board space she picks does not say WHICH minion, so the game now works that out from the rulebook and, when more than one kind could come back, asks her. Asking twice in one step turned out to be the hard part: a saved game reloaded in the middle of that second question forgot the first answer and asked for the space again. That is fixed, and the same shape is now flagged on an older card that shares it. Before it, **8.35z28** through **8.35z33** were six pieces of work built in parallel and landed together: six more of the game's heroes now exist as cards the game can read. Dodger the Warlock, Misa the Samurai, Silverarrow the Pathfinder, Ursafar the Savage, Tali the Spiritcaller and Whisper the Outcast bring a hundred and three of their hundred and fourteen printed faces, each one written out and checked twice against the actual card rather than against itself. The eleven that are not written out are not oversights and each says why it is waiting: six are the weaker "handicap" cards the rulebook only uses at odd player counts, and the rest name a specific thing the game cannot do yet - one of them, a single missing piece on Tali's side, is holding up seven faces on its own. What went in with them: a hero who can perform the action printed on one of her own discarded cards; a hero whose totems stand on the board as one shared supply of three, so putting a new one down picks an old one back up; a card that hands the choice to your opponent rather than to you; a card that lets you take both halves of a "choose one"; and a hero whose ultimate makes the whole board count as the contested zone. None of the six is dealt into a game yet, and that is on purpose: dealing a hero changes what a saved game contains, so it is its own step for each of them, and until then nothing about any existing hero or any existing save has moved - which was checked rather than assumed, on every one of the six landings. Before them, the newest was **8.35z27**: some cards offer a choice of two attacks and let you take both. None of those cards is in the game yet - three of them are coming - so this milestone builds the machinery they all need and proves it on stand-in cards, because getting it wrong once would be getting it wrong three times. Choosing both now plays two complete attacks in turn: each picks its own target from the board as it stands at that moment, each can be blocked separately, and each does its own damage. Somebody knocked out by the first is not there for the second; somebody who survived it can be attacked again, unless the card says "on different targets", in which case they cannot. Throughout, the game still treats the whole thing as one action - which sounds like a detail and is not: a card that stops you repeating an action must not stop this, because these cards never say "repeat". Before it, the newest was **8.35z26**: the practice players that fill empty seats for solo play can now think one move ahead - they take a throwaway copy of the match, try a candidate move on it, see what happens, throw it away, and only then decide. This is only possible where the game's own host is running them; a practice player that joined over the network sees no more than a human in that seat would, and giving one a crystal ball there would mean letting it look at everybody's cards, so it deliberately cannot. The honest headline, though, is a negative one: measured properly, thinking ahead by one move changes what they do in none of three hundred decisions, because the game was already showing them the outcome of each move before they picked. It is left switched on because it costs about one percent of the time they are allowed to think, and because it is the groundwork for looking further ahead than a single move, which is where the useful information actually is. What did improve their play was a single, much duller discovery: they had been preferring the card with the bigger number printed on it, and simply not doing that wins more games. Before it, the newest was **8.35z25**: two of Tigerclaw's attack cards were being played in the wrong order - their own order. Both print "Before the attack: You may move 1 space. Target a unit adjacent to you.", and the game asked whom he was attacking first, then offered him the step. Read as printed, he steps first and then picks somebody next to where he ended up, and that is now what happens. It matters in two ordinary positions: an enemy one step out of reach was simply unavailable before and can now be closed on and attacked, and the reverse trick - naming somebody adjacent and then strolling out of range with the same card - is gone, which is what left the defending player stuck on an unanswerable question in the milestone before this one. Taking a step that leaves nobody adjacent is still allowed and still loses you the card and the turn; the rules call that the player's own rope, and the game does not second-guess it. Before it, the newest was **8.35z24**: a defended attack could reach a state where the defending player was offered cards to block with, and then refused every one of them - and refused "no thanks" as well, so there was no way out of the question at all and the game simply stopped there. It happens when an attacker names somebody to hit and then, with the same card, steps away before the blow lands: two of Tigerclaw's attacks let him do exactly that. The rulebook only asks whether the person being hit is still standing, and the game was also asking whether the attacker could still walk to them. It now asks what the book asks, so the defence is answerable again. It is also what made the practice players lock up solid rather than merely stumble. Before it, the newest was **8.35z23**: the game could save a copy of itself that it then refused to read back. Saving and reloading the exact state of a match is what the undo button rests on, what getting back into your seat after a crash rests on, and what the game's own internal safety net rests on when something goes wrong mid-action - and in two situations the save came out fine and the reload was turned away. One was Xargatha: while her Constrict was waiting to go off, the reload could not recognise where that effect had come from, because it only knew about effects that come from a hero's Ultimate and hers comes from a card already in play. The other was the battle line: if the line was mid-move and had stopped to ask where a small figure should reappear, the reload checked the board against a moment that had already passed and refused. Both are fixed, and thirty-six thousand save-and-reload cycles now pass without one refusal. Before it, the newest was **8.35z22**: the practice players that fill the empty seats when you want to try the game on your own have been given something to think with. Until now they took a legal action at random, and then a simple greedy one; they now weigh the position - how much life each team has left, who holds the board, how close the fight is, whether taking a hit would cost their team a life - and they beat the previous version in 33 of 40 test matches. They are practice opponents for testing and solo play, deliberately so, and they only ever see and choose from exactly what a human in that seat would. One thing worth saying plainly: they cannot think ahead by playing out imagined turns, and they never will in an online seat, because doing that would mean letting them look at everybody else's cards. Before it, the newest was **8.35z21**: the game's own designer, answering a question in the official rules channel, settled a piece of timing this build had been getting wrong. Wiping out the last of the enemy's small figures in the contested zone immediately moves the battle line forward - and when the attack that did it is one a card lets you make a second time, the game used to let that second attack choose its target on the old board and only moved the line once everything was over. The designer's answer is that a repeat is a separate action, so the line moves first: the second attack now picks from the new board, with the swept-away figures gone and the freshly spawned ones already standing. Before it, the newest was **8.35z20**: a live report from the card faces themselves found that Tigerclaw's Blend Into Shadows had its printed secondary backwards - the game offered an extra step of movement the card does not print, and withheld the defense boost it does. It is fixed, and every other hero's card was checked by the same careful method and found correct. Before it, the newest were **8.35z16** through **8.35z19**, four pieces of work built in parallel and landed together. You can now play the printed FOUR-PLAYER game: two a side, in a short or a long version, exactly as the rulebook sets it up on pages 5 and 6 - four Waves worth of life in a quick game, six in a long one, and the four heroes the book itself names for that count. It is chosen on the command line for now; a picker in the lobby is the next step. Two people who pick different games are told so by name instead of being let into each other's match and quietly falling out of step. There is a SANDBOX: a private practice board where you can put heroes where you like, add or take away the small figures, hand somebody a chosen hand of cards, give them a level and some coins, and set how far along the game is - and then just play it, with all the real rules, undo and restart working as they always do, and restart returning you to the board you set up rather than to a dealt one. It is deliberately unavailable in an online seat, and the game refuses to start one that way rather than trusting anybody to remember. And TOOLTIPS EXIST NOW: hovering anything on screen has never once shown you a word in a real build of the game - the little explanations were written, and Unity only ever displays them inside the editor - so every one of them, including the reason a greyed-out button is greyed out, has been invisible to every player until now. Before them, milestone **8.35z15** came from a player's own report while playing: Xargatha's Cleave lets you repeat the attack on a *different* enemy hero, and when the hero she had just hit was the only one standing beside her, the game still asked whether she wanted to - a question whose only honest answer did nothing. It no longer asks. Checking every other card that repeats found the same fault on three more of them, so all four are fixed together, and a card that repeats and *does* have somebody left to hit still asks exactly as before. Before it, milestones **8.35z11** through **8.35z14** were four pieces of work built in parallel and landed together, and between them they change how the game feels more than anything since the board itself. The game now MOVES: cards fly from your hand to the table and flip over when everyone reveals, in the order the printed numbers say they resolve rather than alphabetically; coins fly to the tray they join; a level pops on the hero rail; and every panel and prompt eases into being instead of appearing from nowhere. One "conductor" now paces all of it so things happen one at a time with a beat between them rather than all at once - and it can never make anybody wait, because it is not allowed to touch the game itself, only the pictures of it. Attacks get a spotlight: the interface slides away, the camera pushes in on the two fighters and tilts, both cards stand beside their own figures, the blow plays out framed - including a proper shot-across-the-board for ranged attacks, which used to be a shrug at one end and a flash at the other with nothing in between - and it waits for you to press CONTINUE, or lets go by itself after a few seconds so nobody is ever stuck looking at a screen with no controls on it. The practice bots that fill empty seats now actually fight: they attack when they can, go for whoever is closest to being knocked out, walk toward the fighting instead of wandering, and block with a card when taking the hit would kill them - though what card they commit each round is still a coin flip, on purpose, because choosing that well would change what a practice game is for. When a card fizzles part-way through because something is stopping it, the message now names which hero and which card is doing the stopping instead of leaving you guessing. And a bug from the last round of live play is fixed: your own committed card no longer glows gold while somebody else is taking their turn - gold means "this is yours to answer" and nothing else, though the card does stay raised and lit, because "this is the card I committed" is worth saying. It rests on **8.35z10**, four fixes from the same round of live testing: the game log that drops down from the top now always draws in front of the hero trays instead of sometimes disappearing behind them; the round/life/turn bar at the top of the screen now centers itself where "the game's most important line" belongs, keeping its gold glow, its wording, and the little arrow that opens the log, which now unrolls centered underneath it clear of both rails; the round marker that used to sit as a circle in the middle of that bar now moves instead - it's a thin colored strip above whichever team's hero rail currently holds it, easing smoothly across when it changes hands rather than popping; and the little "fast travel" flag replacing a card's move value now sits right against the boot icon it stands in for instead of floating off to the side over the artwork - and, as a separate small convenience, the exact build you're running now shows in the window's title bar and in a small corner of the lobby screen, so a stale download is obvious at a glance. It rests on **8.35z9**, the end of a five-milestone run landed in one pass: a card that says "you may" no longer offers a button the rules refuse (it affected Living Tsunami and nine other cards); defeated pieces fade out where they stood instead of vanishing; the game keeps a record you can pull down from the top bar and scroll back through; every hero's tray lights while that player is the one being waited on, so the table can see who it is waiting for; and every button shares one look and one press, the lobby's included, which had worn no styling at all. Three of the five came from the user playing the previous build: the slow circling light meant to travel a lit tray had never appeared even once - it was looking for a different kind of element entirely, by the wrong name and the wrong type, and so found nothing and silently animated an empty list; gold, which is supposed to mean "this is yours to answer", was still sitting on a player's own card while somebody else took their turn; and the floating damage numbers were removed outright as not working, with a replacement being designed. It rests on **8.35z4**, whose defect list was the first written by six people playing over the internet rather than by a rehearsal.

It rests on **8.35t**, where a spawned test-driver player filled onto an empty seat for solo practice now dials whatever address the host actually bound, rather than a hardcoded loopback constant that only worked when the host happened to bind loopback too. A join that cannot reach anyone now fails within its own attempt and says so on the host's screen, instead of sitting there forever and leaving a pile of orphaned processes as the only clue.

It rests on **8.35s**, where nothing is ever greyed without saying why. Hovering a control the game will not let you take shows a small pop-up naming the reason, read from the authority's own answer rather than guessed by the screen: a swap or place another hero's standing card has already barred names that hero and card, an action with nothing left to target says so, and every other cause not yet named this way reads a plain, honest "unavailable" instead of an invented explanation. The reason a barred board target draws no ring of its own, and the case where insufficient coins would grey a control, are recorded as open gaps rather than papered over - there is no player-facing coin-priced control to grey yet, and naming one blocked candidate among several would need a fact the game does not publish per-candidate today.
It rests on **8.35p**, where Brogan's three charge cards now move him as soon as he chooses where to land, and only then ask which unit beside him the attack takes - the order the card prints - and an attack whose target its own text named can no longer be taken back by the player who resolved it.
It rests on **8.35n**, where the top bar names the acting hero and what they are doing - your own turn, defense, level up and the rest read in full on your own screen, everyone else's read as who is acting or still owed an answer - and every viewer's board marks that hero's own piece with a gold ring so a bystander can see who is doing something, not only read it. It rests on **8.35j**, where the whole top bar turns gold whenever the game is waiting on you. It was only the narration strip inside it before, and it lit from whether the screen happened to be showing you a control - a fair guess that missed the commonest wait of all, the moment at the top of every round when everyone is choosing a card, because the hand owns that and no control appears. Now one reading answers the question for the bar and the narration together: your commitment, your turn, a decision that is yours to make, a level-up, a defence, a respawn, an agreement, or a finished turn waiting for you to release it. Somebody else's decision leaves your bar dark. It rests on **8.35i**, where a saved game paused in the middle of an attack can be loaded again. Some cards ask a question while an attack is still running - "you may move another unit next to the target" - and saving at exactly that moment produced a file the game then refused to read back, which also broke undo once a match got long enough. The game rebuilds such a question when it loads rather than storing the answer list, and it had been rebuilding it without telling itself which attack was running, so the card had nothing to point at. It rests on **8.35h**, where a broken panel of the HUD began breaking alone. The player's screen is drawn by seven independent panels, and one of them failing used to stop every panel behind it from updating - which is why a single display fault in the 2026-09-03 invited playtest showed up as a whole frozen client while the game itself kept accepting everybody's moves. Each panel now refreshes on its own and a failure is named rather than swallowed, so the board, the card tray, END TURN and UNDO keep working while the broken one sits there. It rests on **8.35g**, where turns no longer end by themselves: when a player finishes resolving their card, the turn stops and waits for them - END TURN, pressed a second time, is what hands it on to the next hero. Until they press it their UNDO still works, and it now reaches back into the action they have just finished, which is the whole point: the misplayed final movement that used to end the turn before anything could be done about it is now the one an undo can still reach. Everybody else waits the moment longer, as they would at a table. It rests on **8.35f**, where each player got an undo of their own - while their cards are resolving, an UNDO button beside END TURN steps that turn back one action at a time, as far as the moment the turn began and no further, never into the commitments, never into somebody else's turn, and never through an attack, because once a target has been chosen the defender has already shown their answer and it cannot be unshown; on **8.35e**, where every seat of a hosted session began rendering the Minion Battle's public team-agreement stage - the choosing side with its own agreement choices, the other side read-only - instead of throwing the presentation exception that froze all six clients of the 2026-09-03 invited playtest, and a seat's hand tray began rendering a hero whose revealed commitment card the seat's privacy-scoped card list deliberately withholds during end-of-round retrieval; on **8.35d**, where in a hosted six-seat session the end-of-round sequence began running by itself, one rulebook stage at a time, stopping only where a stage asks somebody a question, with the level-up card upgrade offered to the one player whose hero bought the level rather than to that player's whole team - nobody presses a shared continue button any more, and nobody can answer a teammate's upgrade; on **8.35a1**, where hosting a private session from the in-game lobby began refusing an unkeyed bind on any address but this machine's own, exactly as the command-line host role always has, because an unkeyed session's link is unencrypted and private per-player data may cross an unencrypted link only inside one machine; and on **8.35c**, where one dedicated seatless host process and six client processes of one disposable Windows build take the six seats through the primitive address/port/session-key lobby and play a complete private match on this machine, using the same build, content, host/session boundary, owner-scoped projections and HUD the invited playtest will use. Each client shows only the seat's private hand and authorized shared state, preserves public tied-Initiative and Minion Battle agreement, disables input while an answer or fresh reconnect projection is outstanding, and gives bounded waiting, delayed, rejection, synchronization, disconnect, reconnect and host-loss feedback. The current private wire is `guards-private-online/5`; protocols 1, 2, 3 and 4 are all rejected, because the seat projection has gained the fact that says whether a seat may step back and then the finished turn that is waiting for its own player, and milestone 8.35g takes the snapshot schema to v35 for that waiting turn it must persist. A same-machine rehearsal is not internet evidence: it proves nothing about relay or NAT traversal, external latency, multi-network connectivity, or real-internet reliability. Milestone **8.36**, the invited six-human internet match, is next proposed and **8.29c** remains deferred pending a reproducible report. The loaded match is the rulebook's six-player Quick Game with six distinct hero sets, three Waves, five Lives per team, twelve minions, and 108 playable cards. All six heroes pass the permanent real-input completion gate, and all 114 roster fronts are independently source-verified. The typed rules engine preserves card/effect continuations, progression, board operations, replay, Undo, and schema-v35 restore. The scaled HUD keeps the readable source-ratio card footprint and shared black perimeter, separates the playable hand from the right-side unavailable fan, retains optional-step context, and links hero plaques and map pieces on hover. Tied Initiative and Minion Battle wait for the applicable public unanimous teammate agreement before submitting their existing rules commands. Facedown information and private fronts remain protected, and the fixed Unity launcher accepts only fresh parseable all-green evidence.

## Requirements

- **Unity `6000.5.9f1`** — the exact version matters; the project is pinned to it in `ProjectSettings/ProjectVersion.txt`.
- **Windows** for the validation tooling and for the player-build smoke gate, which targets Win64. macOS and iOS are declared target platforms but are not yet supported. The toolchain was made portable at milestone 6.1d — paths are separator-agnostic and the Unity/Hub locations come from `GUARDS_UNITY_PATH` and `GUARDS_UNITY_HUB_PATH` or platform probing — and was confirmed on a non-Windows host (Linux, PowerShell 7) at milestone 6.1l, which corrected the three portability defects the first non-Windows runs exposed.
- URP 17.5, with one checked-in pipeline active globally and at every quality level.

## Getting started

1. Open the project folder in Unity Hub with editor version `6000.5.9f1`.
2. Open the only scene: `Assets/Scenes/Milestone1_2_HexGrid.unity`.
3. Press Play. The scene's composition root builds the match session, board, and HUD at runtime — most of what you see is generated, not authored, so the scene looks nearly empty when not running.

The composition root does not run outside Play Mode unless you opt in: `MatchSceneCompositionRoot` has a serialized `composeInEditMode` flag, off by default. Enable it only to preview the board in the editor, and do not save the scene while it is enabled — edit-mode composition regenerates the whole board on every domain reload and can serialize generated objects into the scene.

## Running the tests

Tests are split into Edit Mode and Play Mode assemblies under `Assets/Tests/`. Run them from Unity's **Window → General → Test Runner**, or through the project's fixed launcher:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Invoke-UnityValidation.ps1
```

Unity validation can take well over the default command timeout. Give it at least 15 minutes and do not kill the process if a wrapper times out.

The Unity-free test majority (272 tests at milestone 6.1t) also runs on any OS with a .NET 10 SDK, no Unity required:

```
dotnet test Tools/DotnetTests/GuardsDigital.DotnetTests.csproj
```

Two validators run without Unity and are fast:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Validate-LivingDocumentation.ps1
```

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Validate-BoardMapSpecification.ps1
```

The player-build smoke gate builds a real Windows player, runs it, and requires it to reach a configured match and complete one authoritative command. It catches what no Editor test can — an unresolved shader, a missing resource, a stripped type — because those only appear in a built player:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Invoke-PlayerBuildSmoke.ps1
```

## How the code is organized

| Path | Role |
| --- | --- |
| `Assets/GuardsDigital/Core/` | Pure C# rules, state, board, cards, snapshots, replay. No Unity references — enforced by assembly definition and by test. |
| `Assets/GuardsDigital/Application/` | Command dispatch, projections, the `IMatchSession` port. Also Unity-free. |
| `Assets/GuardsDigital/Presentation/` | Unity views, presenters, input. Passive: it forwards typed commands and renders immutable projections. It never decides rules. |
| `Assets/Tests/` | Edit Mode and Play Mode test assemblies. |
| `Tools/` | Validation and build scripts. |
| `Docs/AI/` | The project's living documentation. |

The one rule worth knowing before changing anything: **presentation never computes a rule outcome.** It submits a typed command through `IMatchSession` and renders whatever projection comes back. There is architecture-conformance test coverage that enforces this mechanically.

## Working agreements

If you contribute here, whether human or agent:

- Work on one approved milestone at a time. Don't drift into adjacent features because they look easy.
- Never invent, simplify, or reinterpret a game rule. The 2nd-printing rulebook and verified card data are authoritative; record any approved deviation in the rules ledger.
- Every behavior change gets focused tests; every bug fix gets a regression test. A failing test blocks the handoff — it is never dismissed as pre-existing.
- Keep rules and state independent of Unity objects, presentation, animation, and audio.
- Commit locally after each completed milestone. Do not add a Git remote or push without explicit authorization.
