## Audit findings and corrective sequence

An out-of-band audit on 2026-08-13 verified fourteen open findings against the source and scheduled them as corrective milestones 6.1c through 6.1k, each closing on a named check observed failing before its fix and passing after. The findings are recorded once in the [Phase 6 audit record](../Archive/Phase-Handoffs/PHASE_6.md#2026-08-13-out-of-band-foundation-audit); the roadmap shard owns their corrective definitions and `TECHNICAL_RISKS.md` owns `RISK-BUILD-001`, `RISK-PERF-001`, and `RISK-STATE-001`.

Milestone 6.1e closed the two composition findings. The board view now publishes the exact sets a rebuild produced, and the composition root consumes those instead of re-discovering children with `GetComponentsInChildren`; in Play Mode a retired view is destroyed through the deferred `Destroy` and stays reachable through a child search until the end of the frame, so re-discovery could admit a doomed object into authoritative board state. Composition no longer runs on an edit-mode domain reload unless the serialized `composeInEditMode` opt-in is enabled, and the seven milestone-1.2 authored hex tiles are removed from the saved scene, which now serializes no object the composition root generates.

Two audit statements were corrected by that work. The seven authored tiles were not stale coordinates destroyed at load: every one is a playable space in the selected map, so they were reconfigured and reused, and one of them supplied the mesh template for all 292 tiles. Edit-mode composition was also not actively dirtying the saved scene; only those seven authored tiles were serialized, so the dirtying was a latent risk that the opt-in gate now forecloses rather than a realized one. `HideFlags.DontSave` was evaluated first and rejected: it keeps generated objects out of the scene but also hides them from `Object.FindObjectsByType`, which the configured presentation and its regressions depend on.

Milestone 6.1g made snapshot restore compile-enforced. Each authority exposes exactly one `Restore` taking one required typed restore-state value and one `CaptureRestoreState` producing it; the seventeen former entry points across eleven types, and the sixteen omission routes their defaulted parameters and state-dropping overloads exposed, are gone. A restore state carries exactly the fields its matching writer emits, validates in its constructor, and declares an explicit `Deconstruct` that the serializer's write path consumes, so a newly persisted field breaks capture, write, read, and restore together rather than being silently dropped or left unwritten. Reconstruction context the snapshot stores elsewhere - participants, definitions, instances, the board, the shared Active-effect lifecycle - stays a separate required argument, so no deconstructed member is one the writer must ignore. Pending Movement and Attack choices are derived during restore rather than persisted; a caller may still supply one to be cross-checked, but that argument is required, so declining the cross-check is stated rather than omitted. The byte format, schema version 6, and the five pinned compatibility digests are unchanged.

Milestone 6.1f gave authoritative card state one mutation path and the match one aggregate root. `CardInstance` and `CardLifecycleAuthority` moved into the `GuardsDigital.Core.CardState` assembly below Core, so card state cannot be mutated from Core, Application, or Presentation at all; the Attack/Defense backend's direct location transition now goes through the lifecycle authority, leaving no duplicated guard to drift. A `MatchAggregate` in Application owns the configuration, board, card-action, and round graphs together with the whole-match rule-event log and the current round's ordered events. The four graphs are installed at one assignment site reached by every path that installs state - initial build, snapshot restore, replay adoption, rollback - and the two event streams are private to the aggregate and published only as immutable snapshots, so an accepted command's state and the events it produced are kept at a single commit boundary and a refused, stale, or faulted command commits neither. The pre-image carries the current round's ordered events explicitly, because the snapshot it restores from carries only the whole-match log. The boundary's guarantee is a rollback rather than the deferred write of `HeroCoinLedger.Award`, which `RISK-STATE-002` records.

Milestones 6.1i and 6.1o together made the session's per-command cost measured rather than inspected, and its failures honest. An accepted command performs one full authoritative serialization and no rule-event envelope encode; a refused command performs one, in every build configuration. The aggregate memoizes its authoritative snapshot and invalidates it only on an accepted commit or a graph replacement, which is sound because 6.1f had already made those the only two ways state is installed. `MatchSessionProjection.DiagnosticSnapshot` is computed on first read from inputs the projection already holds immutably, so no command builds it and the projection stays immutable for a caller holding an older one. A defect thrown in a command path reports as `EngineFault` naming its exception type rather than as a rule rejection, and `Projection.IsHistoryAvailable` distinguishes a session that loaded a snapshot, and so can never record history again, from one that merely has nothing to undo yet.

6.1o corrected two things 6.1i got wrong. The rejected-command comparison had been gated behind a `MatchDiagnosticsMode` the composition root set to `Off` for every non-development build, read as debug-grade self-verification; because that comparison decides whether to roll back, gating it gated the guarantee, and the shipping configuration captured a pre-image it could never act on. The mode is deleted rather than re-defaulted, so no session shape can select a weaker guarantee. Both rule-event streams are now `AppendOnlyEventLog<T>` - an append-only buffer plus a count, whose snapshot is that pair - so a capture copies nothing however long the session has run, and growth or a restore's wholesale replacement leaves earlier snapshots reading the buffer they were handed. The immutable projection keeps that snapshot instead of copying the accumulated log on every refresh.

Milestone 6.1h removed the card-action strategy registry. Every interface it indexed had exactly one implementation and every call site already named a statically-known concrete handler, so its dictionary lookup, cast, and delegate invocation stood between the dispatcher and three backends it already held as fields; the dispatcher now calls them directly, and the strategy identities went with the registry. The ownership boundary is unchanged and still mechanical: `Phase4ArchitectureConformanceTests` rejects an action-specific algorithm in the dispatcher, with its rule re-pointed from the deleted backend interfaces to the algorithm entry points the backends actually call. Milestone 6.1k replaced the substring scan behind it: the rule resolves those entry points as members and reads the calls the compiler emitted, so the fully-qualified evasion measured during 6.1h is now caught.

The same milestone decomposed the two largest Core files, taking the top four from 25.15% of Core to 18.65%. `RoundResolutionAuthority.cs` split by type; `AuthoritativeSnapshotSerializer.cs` split into its load-result types plus a partial static class across setup, round, turn, and card-action subjects, keeping one type and one public surface. `RoundResolutionComposition` replaced the round authority's six optional constructor parameters, taking it from ten parameters to six with none optional; it is a parameter object holding no behaviour, so no defaulting rule moved. The 852-line authority was deliberately left whole.

No material structural defect from the 2026-08-13 audit remains open. The legacy controller and its fixtures were deleted by 6.1c, mutable card state by 6.1f, the broad exception handler by 6.1i, the dispatch ceremony and file concentration by 6.1h, and the brittle structural assertions by 6.1k. `F613-14` closed with milestone 6.1l on 2026-08-13, when the ER2 session's Linux workstation supplied the missing non-Windows host: the confirmation sweep observed three genuine portability failures (backslash exclusion wildcards in the living-document validator's active-file and link-file filters, a PowerShell 7 `[long]` JSON revision failing the board-map library's `[int]` type assertion, and an assignment to the read-only `$home` automatic variable in the Unity launcher), corrected each inside the milestone per its closing check, and recorded every script running to a pass or its documented guard.

One closure in that sequence did not hold on inspection, which is why 6.1o exists. An independent review reopened `F613-08`: 6.1i closed its count half but not its growth half, and the fixture named as the growth evidence measures encoded characters, which cannot observe the array copies that remained. 6.1o closes it and re-retires `RISK-PERF-001` after first reopening it. The review's other four findings - the gated atomicity guarantee above, a missed `RISK-STATE-002` reassessment, archive narratives written after the one-row policy took effect, and status drift across four documents - close there too, the last two through new validator checks so that they fail rather than accumulate.

The architecture fixtures no longer read source text. Since 6.1k they resolve the members and types they forbid through `typeof`/`nameof` and compare them against the calls the compiler emitted, using the test-assembly `ILConformanceScanner`. That reads what the code does rather than how it is spelled, so it survives a rename and catches a fully-qualified, aliased, or lambda-nested call the token lists missed. Each rule is proven non-vacuous against a deliberately violating sample type in the same fixture.

The same amendment retired the per-milestone model/profile contract and added what were then three code-truth validator checks plus four reviewer-owned review dimensions, because the preceding sanctioned reviews at 4.4i and 5.8c both concluded no corrective work was justified while these defects were already present. Both counts are that amendment's history, not current state: the named code-truth check list is maintained in [Testing/POLICY.md](../Testing/POLICY.md), and no review dimension remains reviewer-owned per [ROADMAP.md](../ROADMAP.md).

Milestone 6.1p closed the three limitations 6.1o stated rather than fixed. `GuardsDigital.Application` grants its internals to the Edit Mode test assembly, so the aggregate's commit boundary is asserted by a compile-checked contract test instead of an expression tree naming a private nested type in a string; Core stays closed, so 6.1k's deliberately textual conformance tokens are unaffected. This shard exists because that milestone sharded the implementation inventory rather than compressing it further. `RISK-STATE-002`'s mitigation became a check: `MatchAggregate_HoldsNoStateThatARollbackWouldSilentlyDiscard` classifies every field the aggregate holds, so a new one cannot be added without deciding whether a rollback preserves it.

## Maintenance rule

Maintain this as the standing account of what the audit found, what closed each finding, and which corrections to earlier claims were made. Replace or consolidate a statement when a later milestone changes what is true of it; do not append a milestone-by-milestone journal. Detailed completed outcome, validation, and review evidence belongs once in the commit message body, addressed by SHA, with one row in the indexed phase-handoff archive.
