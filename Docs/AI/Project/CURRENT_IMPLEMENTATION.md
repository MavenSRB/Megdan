Milestone 6.1d's first commit declared the Standard shader in the always-included list and made all four runtime shader lookups throw rather than build a null material, gave `Assets/Editor` its own Editor-only assembly with no project references, made `Assets/Resources/Maps/official-single-lane.json` a generated byte-identical copy of the reviewed specification with drift asserted on every validator run, and replaced the toolchain's hardcoded Unity/Hub paths with environment-override discovery. Its second commit added the player-build smoke gate: a fixed Editor entry point builds a Win64 player, `Tools/Invoke-PlayerBuildSmoke.ps1` launches it, and `PlayerSmokeTestDriver` - attached only when the player is started with an explicit smoke flag - drives one real `DirectorCommand` through `IMatchSession` and reports whether it reached a configured match. Milestone 6.1t ported the cross-platform dotnet harness from the preserved external-review branch: `Tools/DotnetTests/GuardsDigital.DotnetTests.csproj` compiles Core (including CardState), Application, and the Unity-free Edit Mode test files unmodified with a Unity-dependent exclude list acting as a build tripwire, a `System.Text.Json` map-loader shim guarded by a parity fixture, and 272 tests green on the Linux workstation; scope and commands live in `Docs/AI/Testing/DOTNET_HARNESS.md`. Milestone 6.1r gave the board one occupancy seam: an internal `BoardOccupancyIndex` owns per-space occupancy and the one-obstacle-per-space rule for heroes, generic obstacles, and minions through a single collision-checked `Add`, replacing the three per-kind constructor cross-collision blocks and the per-kind scans in move/Fast-Travel commit validation, so a new occupant kind joins by declaring a typed `BoardOccupant` rather than a fourth parallel mechanism; per-kind identity validation is unchanged. Reachability consumes the index through an authority-backed query entry, movement destination validation replays routes on an already-validated `CreateValidationFork` clone instead of reconstructing and revalidating the whole board per accepted step, the occupancy properties are allocation-free live views, and the board joined the compile-enforced restore discipline through `BoardRestoreState`/`CaptureRestoreState`/`Restore` with the wire format unchanged - the five schema-v6 compatibility digests are byte-identical. Milestone 6.1v added the validator's fifth code-truth check: every reflected member and type name in the test corpus must resolve against the declaring type's own source, with deliberate absence assertions carrying an `absence-intended` source marker and a vacuity guard that fails when the scan finds no sites. It matches the raw `typeof(T).GetField("name")` form, its multi-line variants, and the `ReflectedMember.RequiredInstanceField` helper that both test assemblies declare, so routing a call through the helper cannot hide it from the scan. Milestone 6.1u removed the code nothing called - `AdjacentDestinationQuery`, `MovementSessionCompletion` and the return value of `MovementSession.Complete`, the void `Forward*Intent` overloads, and the milestone-0 test shells - and gave the three resolution files one shared `ActionOfferQuery.FindActionDefinition` in place of three byte-identical private copies. Milestone 6.1ap made timing checkpoints resolver-emitted: a card action returns one ordered `ResolutionStep` stream interleaving its rule facts with the timing checkpoints it raises, and the turn authority materializes that stream without reading any fact's kind, replacing the deleted `ApplyActionTiming` rewriter that had inferred checkpoints from produced event kinds. Emitted checkpoint order is unchanged for Movement, Attack with a Defense response, Attack against a minion, and Fast Travel; the deliberate change is that action end now reaches the Active-effect lifecycle before source-card cancellation. Milestone 6.2a established typed Skill and serializable effect execution. A Skill is an ordinary printed action offer resolved by a fourth concrete backend over an immutable, catalog-owned `EffectDefinition`: a flat table of stable nodes with `Sequence`, `Optional`, `Conditional` and `Choose`, where `Mandatory`, `may`, `up to` and `if able` stay four distinct behaviors rather than one failure path. `PendingResolution` carries identity, a continuation stack, completed outcomes and accepted choices - references only, never an `EffectDefinition` object or a handler. Capability dispatch goes through `EffectCapabilityCatalog`, a trusted immutable registry keyed by capability plus revision; action-kind dispatch remains direct concrete composition, unchanged since 6.1h. The snapshot schema is v8 and rejects v7: an Active effect writes identity and runtime state only, with scope, duration, its three lifecycle checkpoints, cancellation conditions, cross-round flag, effect kind, uniqueness key and trigger checkpoints all rebound from the catalog, and pending-choice candidates re-derived from the trusted definition or by re-asking the registered handler rather than read from the payload. Every decision inside an effect frame rides one `AnswerEffectChoice` command carrying the invocation the pending choice projected. One dispatcher owns live typed commands, replay, Undo/restart, restore, ordered events, and immutable projections while three concrete backends, reached directly since 6.1h removed the strategy registry, own handler-specific pending state and mutation. The contextual End Turn control forwards only the projected Hold or Movement Stop command and is suppressed during mandatory choices. Documentation governance milestone 3.11a is complete.

Milestone 6.1a adds the player-facing Minion Battle removal choice over milestone 6.1's unchanged authority. Submitting matches the control against the current projection and forwards only that projected typed invocation through `IMatchSession`; a stale or refused control executes nothing and rebuilds the visible selection from the returned projection.

### Movement and action architecture

Fresh-task independent verification milestone 4.4i inspected the final corrected Phase 4 source, saved-scene route, tests, warnings, runtime paths, raw 4.4h XML/logs, and exact profiling fixture at commit `bfd7258`. It independently confirmed `F44E-01` through `F44E-05`, found no new actionable or gate-blocking observation, and reused the unchanged 4.4h T3 evidence as required. Milestone 5.2 implements Fast Travel as a distinct typed replacement action through the match-session command path. It accepts empty destinations in the actor's current zone or a shared-border adjacent zone, requires no empty-space path, rejects non-adjacent zones and enemy hero/minion presence in either endpoint zone atomically, records ordered replacement/relocation/completion facts, resolves the played card, and suppresses source-card text even when replacing Primary Movement. The application projection exposes only currently eligible Fast Travel replacements and their authoritative legal destinations. The registered backend split is sound for the implemented families, but the outer application/round/turn dispatch and snapshot pending-action discriminator still enumerate those current families, and no structured Skill/effect execution frame exists yet. The approved post-5.8c Phase 6 amendment assigns typed Skill and serializable non-Repeat effect execution to milestone 6.2a, followed by fresh independent verification at 6.2b; Clear and later live effect/action expansion remain downstream of that verification.

### Match state, replay, and configured scope

Authoritative pure C# state currently covers map-scoped identity, the immutable selected map revision, participant `PlayerId`/`HeroId` relationships, initial Tie Breaker, five-card synthetic hands, owned commitment or empty-hand Pass for every configured hero, joint reveal, Initiative and tied-Initiative choice, Hold, printed Movement with cumulative waypoint routes and Stop, adjacent/Ranged Attack with one legal Defense discard or decline, immutable four-turn assignment history, and a resumable end-of-round cursor. On a configured map with one declared starting Battle Zone, Minion Battle compares current Red/Blue minion counts, completes ties without effect, auto-resolves a forced removal set, or pauses on a round-owned typed losing-team choice. That choice carries stable resolution/choice/team/Battle-Zone identities, required count, intrinsic typed candidates, one-at-a-time Heavy-last legal select/deselect sets, current selection, and exact typed invocations. Confirmation removes the exact authoritative selection through ordered non-Heavy-before-Heavy events and advances the owning stage once. Losing the last minion records a typed end-of-round Lane-Push request that remains pending through token/marker cleanup and stops the advance at its consumption stage; since milestone 6.1u that stop rejects with `UnimplementedLanePushConsumption`, which says the rule is unwritten rather than blaming an absent handler, and leaves both the cursor and the request in place for the milestone that will consume them. Eligible cards return to canonical owners; equal-count configured fixtures still complete two uninterrupted synthetic rounds and reuse in the saved validation scene.

Schema-versioned snapshots cover participants, selected map ID/revision, board occupancy, card facets, Initiative/Tie Breaker, current/completed assignments, end-of-round state, pending Movement or Attack/Defense continuations, the complete pending Minion-Battle selection, and an unconsumed end-of-round Lane-Push request. The current persisted snapshot schema is v8, which serializes each remaining minion's current coordinate and explicitly rejects v6; the five representative compatibility fixtures, including a selected Minion-Battle continuation, are pinned at v7 and round-trip byte-identically. Director Undo retains immutable initial scenario inputs plus accepted typed commands, rebuilds fresh authority, replays the retained prefix through the same typed `Execute` path, and verifies byte-identical state/events across two rebuilds. Private replay candidates retain atomic rollback checks but defer unobserved intermediate immutable projection construction; the adopted live session still publishes the one final current projection. Snapshots remain the separate persistence/diagnostics/resynchronization boundary. The read-only HUD exposes Tie Breaker, Undo, Restart, and the rule-event log.

Every enum in the payload is decoded through `SnapshotEnumReader`, which reads the int32 and refuses any value that is not a declared member of that enum under the typed `SnapshotLoadRejectionReason.UnrecognizedEnumValue`, naming the field, the type, and the offending value. The boundary guarantees membership only: rejecting `None`, or a member illegal in a particular position, stays with the domain constructors that own those rules. Declared members are cached per enum type rather than resolved through `Enum.IsDefined`, because `MatchAggregate.Rollback` runs this decoder on every refused or faulted command. Code-truth check 6 in the living-document validator fails on any raw `(SomeEnum)reader.Read…` cast remaining under `Core/Snapshots/`, so the guarantee is uniform across readers rather than dependent on which constructor happens to validate.

The current staged setup declares `official-single-lane` revision 1; places Red and Blue Wasp identities at their team Hero spawn points while retaining five synthetic test cards each; creates three Waves, four Lives per team, and twelve stable standard minions at the reviewed starting-Battle-Zone points; and projects the reviewed Steam/Red and Crystal/Blue circular minion art from authoritative team/type data. Those minions are now authoritative unit obstacles, Defense-modifier sources, and legal typed Attack/Defeat/removal targets. The end-of-round Minion Battle is implemented as described under match state above; displaced-minion correction, minion respawn, Lane-Push consumption, and Lane transitions remain deferred to their later Phase 6 milestones.
