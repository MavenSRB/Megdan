## Current implementation

### Application, configured presentation, and governance

The project has completed roadmap milestones through **6.8f**. Earlier phases established the corrected and independently verified Phase 4 architecture/performance gate, deterministic command-replay Director Undo, the internal rule-event log, the reviewed `official-single-lane` revision 1 map and exact setup, map-bound snapshots, authoritative zone/Lane queries, the pure application port, distinct Movement/Attack-Defense/Fast-Travel/Clear handlers, cached feature projections, bounded diagnostics, and configured saved-scene MVP/input cutover. The configured scene has no legacy controller: its composition root creates the bounded session, peer presenters/passive views, authority-free HUD, and passive board callbacks.

One dispatcher owns live typed commands, replay, Undo/restart, restore, ordered events, and immutable projections, while five concrete backends own handler-specific pending state and mutation and are reached by direct composition rather than through a registry. Action-kind dispatch is that direct composition; capability dispatch alone is data-driven lookup through `EffectCapabilityCatalog`, because a capability reference arrives as data inside the definition the resolver is walking and cannot be named at compile time. The contextual End Turn control forwards only the projected Hold or Movement Stop command and is suppressed during mandatory choices.

A Skill is an ordinary printed action offer resolved over an immutable, catalog-owned `EffectDefinition`: a flat table of stable nodes with `Sequence`, `Optional`, `Conditional` and `Choose`, where `Mandatory`, `may`, `up to` and `if able` stay four distinct behaviors rather than one failure path. `PendingResolution` carries identity, a continuation stack, completed outcomes and accepted choices - references only, never an `EffectDefinition` object or a handler, so the snapshot written from it has nowhere to put semantics. Every decision inside an effect frame rides one `AnswerEffectChoice` command carrying the invocation the pending choice projected, including the token and marker decisions described below. Presentation forwards those invocations and nothing else: the round view renders a paused frame's projected options and withholds the actions, Fast-Travel offers and End Turn control the authority would refuse while it stands. Since milestone 6.2c the Skill seams hold the same bar as Movement and Attack: starting a Skill revalidates the offer against the authoritative offer set and invocation context through the shared Core prevalidation, and the effect-answer path prechecks pending identity and source-card state so a bad state rejects with a typed reason instead of faulting at completion. Refusals report Skill-specific rejection reasons, Skill facts materialize under their own `SkillActionProgressed` turn event kind, a paused Skill frame suppresses the projected Fast-Travel options exactly as paused Movement and Attack do, and snapshot restore re-derives a paused capability's candidates with the node's input bindings rebuilt from the persisted completed outcomes through the resolver's own binding path.

Board occupancy has one seam: an internal per-space index owns the one-obstacle-per-space rule for heroes, generic obstacles, minions, and tokens through a single collision-checked add, so a new occupant kind joins by declaring a typed occupant rather than a parallel mechanism, and per-kind identity validation stays with each kind. Reachability consumes that index through an authority-backed query entry. Timing checkpoints are resolver-emitted: a card action returns one ordered step stream interleaving its rule facts with the checkpoints it raises, and the turn authority materializes that stream without reading any fact's kind. The cross-platform dotnet harness compiles Core, Application, and the Unity-free Edit Mode tests unmodified, with a Unity-dependent exclude list acting as a build tripwire and a map-loader shim guarded by a parity fixture; scope and commands live in `Docs/AI/Testing/DOTNET_HARNESS.md`. Documentation governance milestone 3.11a is complete.

Per-milestone outcome, validation, and review evidence for the milestones summarized above lives once in each commit message body, addressed by SHA from the [Phase 6 archive](../Archive/Phase-Handoffs/PHASE_6.md), per this file's maintenance rule.

### Movement and action architecture

Fresh-task independent verification milestone 4.4i inspected the final corrected Phase 4 source, saved-scene route, tests, warnings, runtime paths, raw 4.4h XML/logs, and exact profiling fixture at commit `bfd7258`. It independently confirmed `F44E-01` through `F44E-05`, found no new actionable or gate-blocking observation, and reused the unchanged 4.4h T3 evidence as required. Milestone 5.1 then integrated the segmented typed Movement continuation on the exact selected map: shortest and deliberately longer cumulative waypoint routes to the same destination commit their selected ordered adjacent steps through the configured match session, a typed evaluator applies prevention or a distance limit once at Movement-action start, and the effective allowance is captured in existing pending state for continuation, restore, replay, and Undo boundaries.

Milestone 5.2 implements Fast Travel as a distinct typed replacement action through the match-session command path. It accepts empty destinations in the actor's current zone or a shared-border adjacent zone, requires no empty-space path, rejects non-adjacent zones and enemy hero/minion presence in either endpoint zone atomically, records ordered replacement/relocation/completion facts, resolves the played card, and suppresses source-card text even when replacing Primary Movement. The application projection exposes only currently eligible Fast Travel replacements and their authoritative legal destinations. Milestone 5.2a makes the configured passive HUD show an eligible replacement as a `FAST TRAVEL` button while leaving normal actions and an unhighlighted board as the default; only explicit button selection exposes that exact destination set. A highlighted coordinate then submits the existing typed `PerformFastTravel` command through `BoardInteractionPresenter` and `IMatchSession`; presentation performs no zone, enemy-presence, or destination-legality calculation. Replay and Undo use the same command path.

The registered backend split is sound for the implemented families. Movement and Attack/Defense retain their serializable pending continuations; Fast Travel and Clear are immediate replacement backends, while Skill owns the catalog-bound effect frame and its serializable pending continuation. Clear deliberately uses the existing direct replacement seam rather than implementing the still-deferred generic `ReplaceAction` effect node. The outer application/round/turn dispatch continues to enumerate authority-level command families, while choices inside an effect definition use the shared `AnswerEffectChoice` command.

### Minions, timing, combat, and rewards

Milestone 5.3 binds the twelve existing configured standard-minion records directly into authoritative board state. Their stable identities, teams, intrinsic Melee/Ranged/Heavy types, map-qualified spaces, and coordinates now enforce one-obstacle-per-space construction, Movement destination/transit blocking, and relocation emptiness without a presentation-derived or parallel minion representation. A discarded Defense card's typed value now adds rulebook minion contributions with stable `MinionId` provenance: +1 per adjacent friendly Melee/Heavy, -1 per adjacent enemy Melee/Heavy, and -1 per enemy Ranged within radius 2. Decline/no legal card still produces no Defense Total. Restore and session snapshot loading rebind the immutable configured minion collection and revalidate pending Defense contributions without a schema-version change. Milestone 6.1s made that position authoritative mutable state: a sealed `MinionOccupancy` carries a minion's identity, team, type, spawn, current space and coordinate, and is replaced through `WithPosition` so reference-identity change detection in the presentation refresh path still holds. `QuickGameMinionSetupState` returns to setup-only duty, converted at the board-authority boundary. Authority-internal `TryCommitMinionMove` validates identity, playable-space membership, and index occupancy, replaces the list entry, keeps the 6.1r occupancy index synchronized, and reports a typed `MinionMoveResult`; no `DirectorCommand` or session exposure exists yet, because the consumers arrive with Object Push (6.4) and Lane Push (6.9-6.11). The snapshot writes each remaining minion's identity and current coordinate and restores the position from the stream rather than reconstructing it from setup placements, advancing `CurrentSchemaVersion` to 7 and explicitly rejecting v6.

Timing is pure named checkpoints plus a validated serializable Active-effect lifecycle. Definition content owns affected scope, trigger set, uniqueness key, `This Turn`/`This Round`/`Next Turn`/`Next Turn after Playing Cards` duration, creation/activation/expiration anchors, cancellation conditions, cross-round policy, and the declared modifications the effect supplies; an instance carries controller/team, affected hero, source card/action, creation order, phase, and activation anchors. Every live effect is visited at every checkpoint, and the context hero narrows only the identity-targeted concerns - activation targeting, triggers, and `AffectedHeroDefeated` cancellation - so a Hero-scoped effect reaches its own expiration window regardless of which hero is acting. Uniqueness suppression compares the declared scope identity rather than one global key namespace, so different controllers activating the same definition coexist. Dormant/active/ended state and Ultimate/token/marker continuous sources round-trip in the current schema, and typed lifecycle facts stay deterministic through live execution, restore plus continuation, replay, and retained-prefix Undo. Printed-text parsing and Wasp content remain absent; the current duration vocabulary permits expiration only at the turn-only and round checkpoints.

Milestone 5.5 adds pure Defeat-reward accounting over the participant collection. A typed Defeat outcome names its stable source/target, defeated team, acting hero, and already-verified Defeat/Assist amounts; deterministic typed coin-gain operations record recipient hero/team, reward kind, minimum/failure contract, and before/after balances. The acting hero receives the Defeat award, every other friendly participant can receive the Assist award, duplicate outcomes and invalid/friendly sources reject without mutation, and all recipients are planned atomically before balances change. A linked removal result remains a separate fact, so prevented removal cannot erase or duplicate an awarded Defeat. Exact hero-Level/lowest-Tier amount derivation, Attack integration, persistence, and UI remain with their later owning milestones.

Milestone 5.6 integrates enemy minions into typed synthetic Attack targeting. Non-Ranged requires adjacency; Ranged uses current typed Range; Heavy remains Immune while a friendly non-Heavy remains in the starting Battle Zone. A legal minion target skips Defense and hero-only Attack Total comparison, records ordered Defeat, 2-coin Melee/Ranged or 4-coin Heavy reward, removal attempt, and removed facts, resolves the attacking turn card, and mutates authoritative occupancy. Snapshot schema version 4 persists remaining-minion identities, reward balances, and awarded-outcome idempotency; version 3 rejects. The unconfigured compatibility drill remains explicitly minion-free and its current Movement-value/continuation regressions are green.

Milestone 5.8 completes the verified general synthetic Hero Attack/Defense order. Stable target validation precedes Action Start/Before Attack, typed Attack Total, defender-owned response, explicit Block-or-numeric comparison, After Attack, and action end. Non-Ranged adjacency and Ranged distance remain the shared target paths; printed, minion, item, card-text, and Active-effect contribution kinds retain typed provenance while only verified synthetic printed/minion values are populated. ### Match state, replay, and configured scope

Authoritative pure C# state currently covers map-scoped identity, the immutable selected map revision, participant `PlayerId`/`HeroId` relationships, initial Tie Breaker, five-card synthetic hands, owned commitment or empty-hand Pass for every configured hero, joint reveal, Initiative and tied-Initiative choice, Hold, printed Movement with cumulative waypoint routes and Stop, adjacent/Ranged Attack with one legal Defense discard or decline, immutable four-turn assignment history, and a resumable end-of-round cursor. On a configured map with one declared starting Battle Zone, Minion Battle compares current Red/Blue minion counts, completes ties without effect, auto-resolves a forced removal set, or pauses on a round-owned typed losing-team choice. That choice carries stable resolution/choice/team/Battle-Zone identities, required count, intrinsic typed candidates, one-at-a-time Heavy-last legal select/deselect sets, current selection, and exact typed invocations. Confirmation removes the exact authoritative selection through ordered non-Heavy-before-Heavy events and advances the owning stage once. Losing the last minion records a typed end-of-round Lane-Push request that remains pending through token/marker cleanup and stops the advance at its consumption stage; since milestone 6.1u that stop rejects with `UnimplementedLanePushConsumption`, which says the rule is unwritten rather than blaming an absent handler, and leaves both the cursor and the request in place for the milestone that will consume them. Eligible cards return to canonical owners; equal-count configured fixtures still complete two uninterrupted synthetic rounds and reuse in the saved validation scene.

Tokens and markers are authoritative components with stable instance identity and a finite supply, both taken from a trusted immutable catalog that owns supply size, display name, token properties, and marker return condition. A placed token is a board occupant: it joins the shared occupancy index by declaring a typed occupant, so it blocks movement, adjacent moves, and every other occupancy consumer without any of them learning that tokens exist, and no per-kind collision block or commit scan was added. Its trusted definition supplies immutable property declarations; the placed instance derives stable `TokenProperty` continuous sources that remain while that token is placed, never enter `ActiveEffectLifecycle`, and do not end when its source card resolves or the placing hero leaves the board. A marker is an attachment with an owner, a holder, a source, and an explicit return condition, and carries no coordinate at all. What remains in either supply is derived from the catalog total minus what is placed or held rather than stored, so the two can never disagree. Placement, the rulebook's short-supply reclamation, marker give, and marker return execute as registered effect capabilities on the milestone 6.2a frame; every decision inside them rides the existing `AnswerEffectChoice` command, and no token-specific pending-choice class, projection property, or continuation arm exists.

Modifiers, restrictions, permissions, immunity, and `Counts As` are one contract rather than five mechanisms. An immutable typed declaration states what it does, an applied record binds it to the rules object it affects and the live source supplying it, and one set answers every question in a canonical order: the revealed Tie-Breaker side first, then the source's creation sequence, then its stable identity, without flipping the coin. Declarations are definition content on an Active-effect definition and on a token property, so nothing about a rule enters the snapshot; a restored effect or token rebinds to the trusted catalog and supplies the same modifications again. The live set is derived per command from Active-effect instances in their active phase plus currently placed tokens, so a dormant `Next Turn` effect supplies nothing until it activates and a removed token stops supplying immediately. Every rules-consuming command and query seam takes that set as a required parameter rather than an optional default - `RuleModificationSet.Empty` is the named no-modification value, a genuinely rule-free call site states it, and a reflection conformance rule fails any seam that reintroduces an optional declaration - so a caller can no longer silently resolve against no modifications. Consumers name the query they use: the Defense value composes typed Active-effect and continuous contributions beside the printed icon and the p.14 minion modifiers with each source discriminator intact; the Attack target query refuses a declared-immune unit while presence counts it; effective-type and intrinsic-kind queries stay separate, and the intrinsic one accepts no modification set at all, so a hero counting as a minion is a minion for type-based rules and still a hero for identity, ownership, occupancy, supply, and p.18's miniature exception; the Fast-Travel offer disappears under a restriction naming it rather than failing later; and one obstacle query owns p.18's classification, honouring the Move-Through permission for transit while refusing every unit an obstacle endpoint. That classification is three-way: a playable space may hold an occupant, a declared terrain space of the selected map exists and is permanently an obstacle - crossable under the permission at ordinary cost, never an endpoint, never occupied, never placed on, and outside every zone, spawn, and occupancy surface - and a coordinate off the map is nothing that any permission answers. The movement board walks playable and terrain cells alike and lets the transit and endpoint predicates decide; route commitment refuses a terrain endpoint under its own `DestinationTerrain` reason. That permission now has its Movement consumer. Reachability asks the obstacle query p.18's two separate questions - an occupied space is traversable only for a mover holding the permission, and is a legal endpoint for nobody - and a chosen route commits as one transaction that asserts occupancy only at its endpoint, so a passed-through space is entered and left without ever being occupied. Entering costs the same either way, and a route crossing nothing occupied produces exactly the events and state the former per-space walk did. Every Active-effect creator mints its instance identity through the one shared contract `ActiveEffectInstanceIdentity.Mint`, composing source card, action, node, round, and turn with the definition, so identity distinguishes activations: a card replayed in a later round creates a fresh instance rather than colliding with the spent one, re-execution inside one resolution stays a legal no-op, and a conformance rule forbids composing an effect ID anywhere else. One configured card supplies these rules in an ordinary match: Red Bulwark's printed Primary Attack is replaced by a three-mode Skill naming the registered value-modifier, restriction and permission capabilities, so the card is only the stable source and the acting hero is always the affected object. Its `This Turn`, `This Round` and `Next Turn` sources make those lifetimes observable end to end. The card keeps its identity, Initiative, printed Secondary Movement and Defense reaction under a new content revision, which is all that reaches the wire.

Clear is an immediate value-free general replacement offered only for a current replaceable Attack. One `PerformClear` command carries a canonical unique token-identity subset, and Core revalidates the source offer, actor presence, adjacency, and whole selection before removing anything. Empty selection is legal. Accepted resolution removes exactly the chosen stable instances in canonical board order, emits Clear-specific start/removal/completion facts between Action Started/Ended checkpoints, suppresses all replaced Attack text and facts, resolves the source card, and follows the ordinary Initiative, snapshot, replay, Undo, and rule-event-log paths. Separately, the board exposes only the mandatory pre-Spawn token-clearance commit for a validated current Spawn point; complete supply, eligibility, destination, occupant creation, events, and choices remain milestone 6.5's general Spawn capability. Displacement, Swap/Replace/general Remove, and end-of-round or defeat cleanup triggers remain later Phase 6 work; presentation still has no component or Clear-specific surface.

Schema-versioned snapshots cover participants, selected map ID/revision, board occupancy, card facets, Initiative/Tie Breaker, current/completed assignments, end-of-round state, pending Movement, Attack/Defense, or Skill continuations, the complete pending Minion-Battle selection, and an unconsumed end-of-round Lane-Push request. The current persisted snapshot schema is v9, which adds a placed-token section to the board and an attached-marker section to the round and explicitly rejects v8. Neither milestone 6.3 nor 6.8 changes a wire field; both move registered content identity instead. The synthetic Hazard definition is at revision 3 because catalog content now supplies its property declaration and that property's typed rule, and the capability registration list carries the five synthetic modification capabilities. A payload naming a superseded revision or a capability set this build does not register rejects rather than silently acquiring current semantics; no persisted state exists outside the test corpus. The seven representative fixtures are re-pinned at v9 and round-trip byte-identically, and the aggregate-invariance equality groups remain unchanged. Director Undo retains immutable initial scenario inputs plus accepted typed commands, rebuilds fresh authority, replays the retained prefix through the same typed `Execute` path, and verifies byte-identical state/events across two rebuilds. Private replay candidates retain atomic rollback checks but defer unobserved intermediate immutable projection construction; the adopted live session still publishes the one final current projection. Snapshots remain the separate persistence/diagnostics/resynchronization boundary. The read-only HUD exposes Tie Breaker, Undo, Restart, and the rule-event log.

Every enum in the payload is decoded through `SnapshotEnumReader`, which reads the int32 and refuses any value that is not a declared member of that enum under the typed `SnapshotLoadRejectionReason.UnrecognizedEnumValue`, naming the field, the type, and the offending value. The boundary guarantees membership only: rejecting `None`, or a member illegal in a particular position, stays with the domain constructors that own those rules. Declared members are cached per enum type rather than resolved through `Enum.IsDefined`, because `MatchAggregate.Rollback` runs this decoder on every refused or faulted command. Code-truth check 6 in the living-document validator fails on any raw `(SomeEnum)reader.Read…` cast remaining under `Core/Snapshots/`, so the guarantee is uniform across readers rather than dependent on which constructor happens to validate.

The current staged setup declares `official-single-lane` revision 1; places Red and Blue Wasp identities at their team Hero spawn points while retaining five synthetic test cards each; creates three Waves, four Lives per team, and twelve stable standard minions at the reviewed starting-Battle-Zone points; and projects the reviewed Steam/Red and Crystal/Blue circular minion art from authoritative team/type data. Those minions are now authoritative unit obstacles, Defense-modifier sources, and legal typed Attack/Defeat/removal targets. The end-of-round Minion Battle is implemented as described under match state above; displaced-minion correction, minion respawn, Lane-Push consumption, and Lane transitions remain deferred to their later Phase 6 milestones.
