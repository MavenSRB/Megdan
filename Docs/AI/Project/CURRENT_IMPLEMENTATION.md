The project has completed roadmap milestones through **6.1k**. ### Movement and action architecture

Fresh-task independent verification milestone 4.4i inspected the final corrected Phase 4 source, saved-scene route, tests, warnings, runtime paths, raw 4.4h XML/logs, and exact profiling fixture at commit `bfd7258`. ### Known foundation defects and governance state

An out-of-band audit on 2026-08-13 verified fourteen open findings against the source and scheduled them as corrective milestones 6.1c through 6.1k, each closing on a named check observed failing before its fix and passing after. The findings are recorded once in the [Phase 6 audit record](../Archive/Phase-Handoffs/PHASE_6.md#2026-08-13-out-of-band-foundation-audit); the roadmap shard owns their corrective definitions and `TECHNICAL_RISKS.md` owns `RISK-BUILD-001`, `RISK-PERF-001`, and `RISK-STATE-001`.

Milestone 6.1e closed the two composition findings. The board view now publishes the exact sets a rebuild produced, and the composition root consumes those instead of re-discovering children with `GetComponentsInChildren`; in Play Mode a retired view is destroyed through the deferred `Destroy` and stays reachable through a child search until the end of the frame, so re-discovery could admit a doomed object into authoritative board state. Composition no longer runs on an edit-mode domain reload unless the serialized `composeInEditMode` opt-in is enabled, and the seven milestone-1.2 authored hex tiles are removed from the saved scene, which now serializes no object the composition root generates.

Two audit statements were corrected by that work. The seven authored tiles were not stale coordinates destroyed at load: every one is a playable space in the selected map, so they were reconfigured and reused, and one of them supplied the mesh template for all 292 tiles. Edit-mode composition was also not actively dirtying the saved scene; only those seven authored tiles were serialized, so the dirtying was a latent risk that the opt-in gate now forecloses rather than a realized one. `HideFlags.DontSave` was evaluated first and rejected: it keeps generated objects out of the scene but also hides them from `Object.FindObjectsByType`, which the configured presentation and its regressions depend on.

Milestone 6.1g made snapshot restore compile-enforced. Each authority exposes exactly one `Restore` taking one required typed restore-state value and one `CaptureRestoreState` producing it; the seventeen former entry points across eleven types, and the sixteen omission routes their defaulted parameters and state-dropping overloads exposed, are gone. A restore state carries exactly the fields its matching writer emits, validates in its constructor, and declares an explicit `Deconstruct` that the serializer's write path consumes, so a newly persisted field breaks capture, write, read, and restore together rather than being silently dropped or left unwritten. Reconstruction context the snapshot stores elsewhere - participants, definitions, instances, the board, the shared Active-effect lifecycle - stays a separate required argument, so no deconstructed member is one the writer must ignore. Pending Movement and Attack choices are derived during restore rather than persisted; a caller may still supply one to be cross-checked, but that argument is required, so declining the cross-check is stated rather than omitted. The byte format, schema version 6, and the five pinned compatibility digests are unchanged.

Milestone 6.1f gave authoritative card state one mutation path and the match one aggregate root. `CardInstance` and `CardLifecycleAuthority` moved into the `GuardsDigital.Core.CardState` assembly below Core, so card state cannot be mutated from Core, Application, or Presentation at all; the Attack/Defense backend's direct location transition now goes through the lifecycle authority, leaving no duplicated guard to drift. A `MatchAggregate` in Application owns the configuration, board, card-action, and round graphs together with the whole-match rule-event log and the current round's ordered events. The four graphs are installed at one assignment site reached by every path that installs state - initial build, snapshot restore, replay adoption, rollback - and the two event streams are private to the aggregate and published only as read-only views, so an accepted command's state and the events it produced are kept at a single commit boundary and a refused, stale, or faulted command commits neither. That boundary also corrected a defect the refactor exposed: the rollback previously discarded the current round's ordered events, because its pre-image is a serialized snapshot and the snapshot carries the whole-match log rather than the round's slice. The pre-image now carries that slice in memory. The commit boundary's guarantee is a rollback rather than the deferred write of `DefeatRewardAccounting.Award`, which `RISK-STATE-002` records.

Milestone 6.1i made the session's per-command cost measured rather than inspected, and its failures honest. An accepted command performs one full authoritative serialization and no rule-event envelope encode; a refused command performs one with self-verification on and none with it off. The aggregate memoizes its authoritative snapshot and invalidates it only on an accepted commit or a graph replacement, which is sound because 6.1f had already made those the only two ways state is installed. `MatchSessionProjection.DiagnosticSnapshot` is computed on first read from the authoritative snapshot and event list the projection already holds immutably, so no command builds it and the projection stays immutable for a caller holding an older one. The rollback pre-image carries the rule-event log and the current round's events as in-memory arrays rather than an encoded envelope, so nothing on the command path grows with session length. A typed `MatchDiagnosticsMode` gates the self-verification and the composition root selects it - `Verified` for a development build, `Off` otherwise - so Core and Application still contain no preprocessor branches and no Unity build symbols; the gate covers the check, never the rollback pre-image that makes a refused command leave no partial state. A defect thrown in a command path reports as `EngineFault` naming its exception type rather than as a rule rejection, and `Projection.IsHistoryAvailable` distinguishes a session that loaded a snapshot, and so can never record history again, from one that merely has nothing to undo yet; the Undo control receives that distinction.

Milestone 6.1h removed the card-action strategy registry. Every interface it indexed had exactly one implementation and every call site already named a statically-known concrete handler, so its dictionary lookup, cast, and delegate invocation stood between the dispatcher and three backends it already held as fields; the dispatcher now calls them directly, and the strategy identities went with the registry. The ownership boundary is unchanged and still mechanical: `Phase4ArchitectureConformanceTests` rejects an action-specific algorithm in the dispatcher, with its rule re-pointed from the deleted backend interfaces to the algorithm entry points the backends actually call. Milestone 6.1k replaced the substring scan behind it: the rule resolves those entry points as members and reads the calls the compiler emitted, so the fully-qualified evasion measured during 6.1h is now caught.

The same milestone decomposed the two largest Core files. `RoundResolutionAuthority.cs` split by type into the turn slot, event, result, and authority files; `AuthoritativeSnapshotSerializer.cs` split into its load-result types plus a partial static class across setup, round, turn, and card-action subjects, keeping one type and one public surface. The top four Core files fell from 25.15% of Core to 18.65%. `RoundResolutionComposition` replaced the round authority's six optional constructor parameters, taking it from ten parameters to six with none optional; it is a parameter object holding no behaviour, so no defaulting rule moved. The 852-line authority was deliberately left whole rather than split further.

No material structural defect from the 2026-08-13 audit remains open. The legacy controller and its fixtures were deleted by 6.1c, mutable card state by 6.1f, the ungated self-verification and the broad exception handler by 6.1i, the dispatch ceremony and file concentration by 6.1h, and the brittle structural assertions by 6.1k. The corrective sequence 6.1c-6.1k is complete; every finding except `F613-14` is closed on a recorded failing-then-passing check transition. `F613-14` stays with the `[!]` blocked milestone 6.1l, which needs a non-Windows host this machine does not have.

The architecture fixtures no longer read source text. Since 6.1k they resolve the members and types they forbid through `typeof`/`nameof` and compare them against the calls the compiler emitted, using the test-assembly `ILConformanceScanner`. That reads what the code does rather than how it is spelled, so it survives a rename and catches a fully-qualified, aliased, or lambda-nested call the token lists missed. Each rule is proven non-vacuous against a deliberately violating sample type in the same fixture.

The same amendment retired the per-milestone model/profile contract and added three code-truth validator checks plus four mandatory independent-review dimensions, because the preceding sanctioned reviews at 4.4i and 5.8c both concluded no corrective work was justified while these defects were already present.

The project does not yet implement current-Battle-Zone changes, Lane-Push consumption/transition/respawn, player-facing Minion-Battle removal UI, the final official six-player Quick Game setup, resolve-without-action, real Wasp content, general card-text effects, complete hero Attack consequences, the remaining concrete end-of-round subsystems, networking, production animation/audio, or build/distribution work.
