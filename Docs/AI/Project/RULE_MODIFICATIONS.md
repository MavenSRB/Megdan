## Rule modifications and their consumers

Modifiers, restrictions, permissions, immunity, and `Counts As` are one contract rather than five mechanisms. An immutable typed declaration states what it does, an applied record binds it to the rules object it affects and the live source supplying it, and one set answers every question in a canonical order: the revealed Tie-Breaker side first, then the source's creation sequence, then its stable identity, without flipping the coin. Declarations are definition content on an Active-effect definition and on a token property, so nothing about a rule enters the snapshot; a restored effect or token rebinds to the trusted catalog and supplies the same modifications again. The live set is derived per command from Active-effect instances in their active phase plus currently placed tokens, so a dormant `Next Turn` effect supplies nothing until it activates and a removed token stops supplying immediately. Every rules-consuming command and query seam takes that set as a required parameter rather than an optional default - `RuleModificationSet.Empty` is the named no-modification value, a genuinely rule-free call site states it, and a reflection conformance rule fails any seam that reintroduces an optional declaration - so a caller can no longer silently resolve against no modifications. The same regime covers every rule-affecting parameter of that surface: the Tie Breaker ordering simultaneous modifications and the rules object a query is asked about, with `TieBreakerState.Unrevealed` and `RuleObject.None` as their named absences. It matters most at immunity, where an omitted actor silently withdrew p.18's "You are never immune to your own actions"; a call site now names its actor or states that the question is the abstract one. Consumers name the query they use: the Defense value composes typed Active-effect and continuous contributions beside the printed icon and the p.14 minion modifiers with each source discriminator intact; the Attack target query refuses a declared-immune unit while presence counts it, and since milestone 6.4 the Object Push capability asks the same question for `RuleActivity.ObjectPush` - the member's first production reader, which is why the configured card carrying a Push immunity is scheduled behind it - dropping an immune unit from the target set while a presence question over the same spaces would still see it, and asking nothing at all of a pushed token, since p.19 states tokens are not units and the rules-object vocabulary has no token member to name; effective-type and intrinsic-kind queries stay separate, and the intrinsic one accepts no modification set at all, so a hero counting as a minion is a minion for type-based rules and still a hero for identity, ownership, occupancy, supply, and p.18's miniature exception; every implemented rule naming a unit type declares which of the two questions it asks in the unit-type question ledger, and the p.13 Heavy-immunity accompaniment clause reads the shared Battle-Zone set that the Minion Battle and p.8's last-minion Lane-Push cause already count, rather than a second derivation of its own, so a hero counting as a minion in the current Battle Zone accompanies and protects its Heavy, while the immune subject stays an intrinsic Heavy miniature and a conformance rule forbids kind reads outside the two queries; the Fast-Travel offer disappears under a restriction naming it rather than failing later; and one obstacle query owns p.18's classification, honouring the Move-Through permission for transit while refusing every unit an obstacle endpoint. That classification is three-way: a playable space may hold an occupant, a declared terrain space of the selected map exists and is permanently an obstacle - crossable under the permission at ordinary cost, never an endpoint, never occupied, never placed on, and outside every zone, spawn, and occupancy surface - and a coordinate off the map is nothing that any permission answers. The movement board walks playable and terrain cells alike and lets the transit and endpoint predicates decide; route commitment refuses a terrain endpoint under its own `DestinationTerrain` reason. That permission now has its Movement consumer. Reachability asks the obstacle query p.18's two separate questions - an occupied space is traversable only for a mover holding the permission, and is a legal endpoint for nobody - and a chosen route commits as one transaction that asserts occupancy only at its endpoint, so a passed-through space is entered and left without ever being occupied. Entering costs the same either way, and a route crossing nothing occupied produces exactly the events and state the former per-space walk did. Every Active-effect creator mints its instance identity through the one shared contract `ActiveEffectInstanceIdentity.Mint`, composing source card, action, node, round, and turn with the definition, so identity distinguishes activations: a card replayed in a later round creates a fresh instance rather than colliding with the spent one, re-execution inside one resolution stays a legal no-op, and a conformance rule forbids composing an effect ID anywhere else. Two configured cards supply these rules in an ordinary match. Red Bulwark's printed Primary Attack is replaced by a three-mode Skill naming the registered value-modifier, restriction and permission capabilities, and Blue Feint's by a two-mode Skill naming the registered immunity and `Counts As` capabilities, so each card is only the stable source and the acting hero is always the affected object. Between them the four delayed lifetimes are observable end to end: `This Turn`, `This Round`, `Next Turn`, and `Next Turn, After Playing Cards`, whose activation anchor is the cards-revealed checkpoint rather than the start of the turn. Blue Feint's modes are what make the two consumers visible from a card a player holds - the Object Push target query refuses the immune hero outright while a presence question still counts it, and the effective-type query sees a minion while the hero miniature, its identity, ownership, occupancy, supply, and p.18's displaced-minion exception are all untouched. Each card keeps its identity, Initiative, printed Secondary Movement and Defense reaction under a new content revision, which is all that reaches the wire.

## The declarable space and its consumers

Every member a definition can declare either changes a production answer or is excluded by name with its reason and the seam its consumer would go in, and a conformance rule enumerates the space from the enums themselves so a new member is undecided until someone decides it. The rule's probes read production seams rather than the set, because the set answers every member by construction and the question is whether any rule asks; where the asking seam needs a match in flight, a second rule asserts the link from that seam to the query the probe read. Restrictions reach every action kind through one shared predicate over the action-to-activity mapping - consulted by the turn's offer set, by the three general-rule offers, and by p.14's Defense response - so a card that first prints a prohibition is obeyed without a new consumer, and the value channels no source modifies stay excluded rather than gaining speculative ones.

A restriction may also name **who** is barred: the affected object itself, or heroes standing in a declared team relation to the source, resolved against the controlling side the applied record already carries. The undirected question - may this object do this itself - is what an offer asks, and a directed query answers the other one, which the Swap and Place capabilities ask at target and piece derivation so a piece the rules will not let this actor move is never offered and then refused. p.19's Swap and p.18's Place are named activities for this, beside Object Push: all three are effect families the rules perform rather than action kinds a hero takes, and both capabilities ask immunity for their own family as well as for the enclosing action's.

A source may also declare a **conditional obstacle overlay**, which names no object at all because it changes what p.18 counts as an obstacle. It is definition content beside the modifications, carries a radius and the arms it declares - spaces inside the disk while a qualifying hero acts from outside, spaces outside it while one acts from within - and is bound at derivation to two live facts: the source hero's current space, which is p.17's Radius moving with its hero, and the hero whose action the set is being derived for. The live set therefore carries the acting object, stated as `RuleObject.None` at a moment when nobody is acting, and the obstacle query answers a question about a space alone. Because p.18 gives the classification one owner, movement, push, and place legality read the same closure by construction; the Place destination question moved onto that query for exactly this reason. p.18's own after-action correction asks with no modifications in effect - it is bookkeeping the rules carry out rather than something a hero performs - and its planner and its commit ask identically.

## Maintenance rule

Corrective milestone 6.5aa centralizes the behavior that supersedes the earlier Attack/Object-Push-only description above. `ImmunityQuery` combines declared exact-activity immunity with standing p.13 Heavy immunity and is called during both candidate derivation and final mutation for Attack, direct Move, Object Push, and Place. Blue Feint's Push immunity therefore removes its hero from Red Needle's Push candidate controls instead of offering a choice that later refuses. The same correction makes Minion Battle consume effective-minion identity: a counts-as hero counts and may be selected, while remaining intrinsically a hero for identity and the approved remove-without-Defeat consequence.
