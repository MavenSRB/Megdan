## Rule modifications and their consumers

Grant-specific unit exclusions are not immunity declarations. `RuleModificationSet.TargetExclusions` carries actor/unit bindings derived from the running Skill-borrow scope; target and operation guards ask `TargetQuery.IsPrevented`, which combines that exclusion with ordinary immunity. `ImmunityQuery` and presence retain their distinct meanings. [The timing contract](../Card-System/TIMING_AND_TRANSITIONS.md#control-flow-and-action-composition) owns the scope's lifetime and persistence.

Modifiers, restrictions, permissions, immunity, and `Counts As` are one contract rather than five mechanisms. An immutable typed declaration states what it does, an applied record binds it to the rules object it affects and the live source supplying it, and one set answers every question in a canonical order: the revealed Tie-Breaker side first, then the source's creation sequence, then its stable identity, without flipping the coin. Declarations are definition content on an Active-effect definition and on a token property, so nothing about a rule enters the snapshot; a restored effect or token rebinds to the trusted catalog and supplies the same modifications again. The live set is derived per command from Active-effect instances in their active phase plus currently placed tokens, so a dormant `Next Turn` effect supplies nothing until it activates and a removed token stops supplying immediately. Every rules-consuming command and query seam takes that set as a required parameter rather than an optional default - `RuleModificationSet.Empty` is the named no-modification value, a genuinely rule-free call site states it, and a reflection conformance rule fails any seam that reintroduces an optional declaration - so a caller can no longer silently resolve against no modifications. The same regime covers every rule-affecting parameter of that surface: the Tie Breaker ordering simultaneous modifications and the rules object a query is asked about, with `TieBreakerState.Unrevealed` and `RuleObject.None` as their named absences. It matters most at immunity, where an omitted actor silently withdrew p.18's "You are never immune to your own actions"; a call site now names its actor or states that the question is the abstract one. Consumers name the query they use: the Defense value composes typed Active-effect and continuous contributions beside the printed icon and the p.14 minion modifiers with each source discriminator intact; the Attack target query refuses a declared-immune unit while presence counts it, and since milestone 6.4 the Object Push capability asks the same question for `RuleActivity.ObjectPush` - the member's first production reader, which is why the configured card carrying a Push immunity is scheduled behind it - dropping an immune unit from the target set while a presence question over the same spaces would still see it, and asking an ordinary pushed token no unit-type question, since p.19 states tokens are not units; a separately declared action-scoped overlay can make a token count as a minion without changing its token identity; effective-type and intrinsic-kind queries stay separate, and the intrinsic one accepts no modification set at all, so a hero counting as a minion is a minion for type-based rules and still a hero for identity, ownership, occupancy, supply, and p.18's miniature exception; every implemented rule naming a unit type declares which of the two questions it asks in the unit-type question ledger, and the p.13 Heavy-immunity accompaniment clause reads the shared Battle-Zone set that the Minion Battle and p.8's last-minion Lane-Push cause already count, rather than a second derivation of its own, so a hero counting as a minion in the current Battle Zone accompanies and protects its Heavy, while the immune subject stays an intrinsic Heavy miniature and a conformance rule forbids kind reads outside the two queries; the Fast-Travel offer disappears under a restriction naming it rather than failing later; and one obstacle query owns p.18's classification, honouring the Move-Through permission for transit while refusing every unit an obstacle endpoint. That classification is three-way: a playable space may hold an occupant, a declared terrain space of the selected map exists and is permanently an obstacle - crossable under the permission at ordinary cost, never an endpoint, never occupied, never placed on, and outside every zone, spawn, and occupancy surface - and a coordinate off the map is nothing that any permission answers. The movement board walks playable and terrain cells alike and lets the transit and endpoint predicates decide; route commitment refuses a terrain endpoint under its own `DestinationTerrain` reason. That permission now has its Movement consumer. Reachability asks the obstacle query p.18's two separate questions - an occupied space is traversable only for a mover holding the permission, and is a legal endpoint for nobody - and a chosen route commits as one transaction that asserts occupancy only at its endpoint, so a passed-through space is entered and left without ever being occupied. Entering costs the same either way, and a route crossing nothing occupied produces exactly the events and state the former per-space walk did. Every Active-effect creator mints its instance identity through the one shared contract `ActiveEffectInstanceIdentity.Mint`, composing source card, action, node, round, and turn with the definition, so identity distinguishes activations: a card replayed in a later round creates a fresh instance rather than colliding with the spent one, re-execution inside one resolution stays a legal no-op, and a conformance rule forbids composing an effect ID anywhere else. Two configured cards supply these rules in an ordinary match. Red Bulwark's printed Primary Attack is replaced by a three-mode Skill naming the registered value-modifier, restriction and permission capabilities, and Blue Feint's by a two-mode Skill naming the registered immunity and `Counts As` capabilities, so each card is only the stable source and the acting hero is always the affected object. Between them the four delayed lifetimes are observable end to end: `This Turn`, `This Round`, `Next Turn`, and `Next Turn, After Playing Cards`, whose activation anchor is the cards-revealed checkpoint rather than the start of the turn. Blue Feint's modes are what make the two consumers visible from a card a player holds - the Object Push target query refuses the immune hero outright while a presence question still counts it, and the effective-type query sees a minion while the hero miniature, its identity, ownership, occupancy, supply, and p.18's displaced-minion exception are all untouched. Each card keeps its identity, Initiative, printed Secondary Movement and Defense reaction under a new content revision, which is all that reaches the wire.

## The declarable space and its consumers

`ControllerAndHeroesInRadius` is consumed by the live modification query: it includes the controller
and in-radius heroes, excludes minions, and retains the declaration's team/activity restrictions.
Trailblazer therefore reaches its controller and friendly heroes through its live Radius Total (printed 4) for Movement
actions, not enemies or card-text Direct Move. The source-linked `SilverarrowCapabilityTests` cover
self, teams, minions and both sides of the radius boundary.

Every member a definition can declare either changes a production answer or is excluded by name with its reason and the seam its consumer would go in, and a conformance rule enumerates the space from the enums themselves so a new member is undecided until someone decides it. The rule's probes read production seams rather than the set, because the set answers every member by construction and the question is whether any rule asks; where the asking seam needs a match in flight, a second rule asserts the link from that seam to the query the probe read. Restrictions reach every action kind through one shared predicate over the action-to-activity mapping - consulted by the turn's offer set, by the three general-rule offers, and by p.14's Defense response - so a card that first prints a prohibition is obeyed without a new consumer, and the value channels no source modifies stay excluded rather than gaining speculative ones.

A restriction may also name **who** is barred: the affected object itself, or heroes standing in a declared team relation to the source, resolved against the controlling side the applied record already carries. The undirected question - may this object do this itself - is what an offer asks, and a directed query answers the other one, which the Swap and Place capabilities ask at target and piece derivation. p.19's Swap and p.18's Place are named activities for this, beside Object Push: all three are effect families the rules perform rather than action kinds a hero takes, and both capabilities ask immunity for their own family as well as for the enclosing action's.

Until milestone 8.35l this shard claimed that asking there meant "a piece the rules will not let this actor move is never offered and then refused". Measurement falsified it: the capabilities did ask, but only where they were reached, and the question that builds the offer never reached them - so a hero standing inside Wasp's Magnetic Dagger was offered a Swap she could not make, spent the card and rulebook p.7's one action on it, and moved nothing. Three things now make the sentence true as written. A selection that declares its consumer is asked about the **output that consumer binds** rather than about the bare candidate, so a selection publishing a minion and a Swap taking that minion's space finally understand each other; the offer applies the selection's own **minimum**, so a pair whose floor is two is refused on a board holding one legal piece rather than offered and stopped; and the feasibility walk carries forward what a node that only publishes a fact - the acting hero's own space, an adjacency reading - would publish, instead of treating publishing as the action having done something, so a Place standing behind such a node is judged rather than skipped. A barred piece is therefore absent from the candidate list, an action with no legal continuation left is greyed, and the greying and the refusal a start would produce are one answer read at two moments.

The refusal also **says who caused it**. `RestrictionQuery.TryGetRestriction` has always returned the applied modification whose source explains the refusal, and every caller discarded it; the Swap and Place capabilities now hand it back, the walk records the first one it meets in execution order, and the offer carries it as `ActionUnavailability` - the barred activity, the controlling hero, the source card, the Active-effect instance. `AppliedRuleModification` carries its source card for the same reason: a player recognises a card, not an effect identity. Presentation composes the words and never re-derives the rule.

A source may also declare a **conditional obstacle overlay**, which names no object at all because it changes what p.18 counts as an obstacle. It is definition content beside the modifications, carries a radius and the arms it declares - spaces inside the disk while a qualifying hero acts from outside, spaces outside it while one acts from within - and is bound at derivation to two live facts: the source hero's current space, which is p.17's Radius moving with its hero, and the hero whose action the set is being derived for. The live set therefore carries the acting object, stated as `RuleObject.None` at a moment when nobody is acting, and the obstacle query answers a question about a space alone. Because p.18 gives the classification one owner, movement, push, and place legality read the same closure by construction; the Place destination question moved onto that query for exactly this reason. p.18's own after-action correction asks with no modifications in effect - it is bookkeeping the rules carry out rather than something a hero performs - and its planner and its commit ask identically.

Milestone 8.19b makes a verified printed Heavy-immunity exception a typed node declaration rather than an all-purpose permission. `ImmunityOverrideDeclaration` names the exact operation and the only supported reason, `PrintedHeavyMinionImmunity`; direct Move and Swap ask both their enclosing activity and their own `RuleActivity.DirectMove`/`RuleActivity.Swap` identity at candidate and commit time. A matching override bypasses only p.13's standing Heavy immunity. An independent source-declared immunity for either queried activity still wins, and an override naming one operation cannot leak into another. The declarable-space conformance rule therefore records `Immunity/DirectMove` as consumed while retaining `Restriction/DirectMove` as a named unsupported arm rather than speculatively making direct Move an action restriction.

Milestone 8.19c adds the roster's persistent source families and one sixth modification kind. An **immunity may now name several activities and the actors it protects against**, which is one sentence on the card rather than four rules: the actor classes are read by the same resolution a restriction's are, so a qualification printed on either family means one thing, and p.18's fixed "you are never immune to your own actions" is applied before any scope is consulted. `ImmunityQuery` is the one asker of the directed question because it holds the participants a team relation resolves against; the set itself answers only the unqualified declarations. An **effective-type overlay** adds a type instead of replacing one - `EffectiveUnitKind.Terrain` is its first member and only an overlay may supply it - so a petrified hero is a hero *and* terrain, keeps its team, occupancy and targetability, and stops being terrain when its source ends. One terrain question answers both the map's printed terrain and an overlaid object, so a card asking "adjacent to terrain" cannot see the rock and miss the hero. A **value modifier may be counted from live state** - an amount per match of a named derived query, resolved wherever the live set is derived, contributing nothing at all at zero - and may be **qualified to the action class it names**, which admits a declaration only for the total that action composes. Each of p.9's four remaining value channels now has exactly one owning query that both the live resolution and its re-derivations ask: `AttackValueQuery` and `MovementValueQuery` are promoted for that reason, beside the existing Range, Radius and Defense totals, and the Initiative total is composed where the turn order reads it.

Milestone 8.19c1 adds a seventh kind, and it is the first that stops the game. A **removal prevention** says the affected object's removal may be bought off, at a typed card price the declaration carries; it is not a qualified immunity, because p.18's immunity is unconditional and answers before anything happens while this one is a decision somebody takes after a Defeat has been recorded and its reward paid, and declining it is a legal answer. A free prevention is refused outright: a source that stops a removal for nothing is p.18's immunity, and one rule with two spellings would answer "may this unit be targeted" two ways. `RemovalPreventionQuery` is its one directed asker, because only something holding the cards can say whether the price can be paid, and the candidates are re-derived when the answer arrives rather than trusted from the pause. The coverage half is the source's own affected scope, so "friendly minions in radius" is stated once by the effect and walks in and out with the disk. A declaration that reaches a hero is inert and says why: p.13 removes a defeated hero on its first line and pays its coins on its fourth, so a hero has no "after the reward and before the removal" moment for the family to stand in, and p.13's own Bolster example is about a minion.

Milestone 9.52's board partition is an Active-effect declaration, not a new immunity or obstacle type. `BoardPartitionRestriction` binds the trusted mode to a chosen, fixed `BoardPartitionLine` occurrence; `RuleModificationQuery` derives the active restrictions and actor position per command. `RuleModificationSet` requires an explicit acting object and space when a partition is present, preserving the no-optional-rule-argument conformance rule. The cross-side question is shared by target, coordinate, area, Movement, Place and Fast Travel consumers; Shift adds a controller-specific absence to object interaction only. Neutral line spaces are neither side. The line origin and axis are persisted in schema v59 because moving the controller destroys any ability to re-derive the original choice.

## Maintenance rule

Corrective milestone 6.5aa centralizes the behavior that supersedes the earlier Attack/Object-Push-only description above. `ImmunityQuery` combines declared exact-activity immunity with standing p.13 Heavy immunity and is called during both candidate derivation and final mutation for Attack, direct Move, Object Push, Place, and Swap. Milestone 8.19b extends that one query with the exact-operation override described above and makes the existing Radius selector consume it too, so automatically affected and explicitly selected units agree. Blue Feint's Push immunity therefore removes its hero from Red Needle's Push candidate controls instead of offering a choice that later refuses; a printed Heavy override never suppresses that declared source. The same correction makes Minion Battle consume effective-minion identity: a counts-as hero counts and may be selected, while remaining intrinsically a hero for identity and the approved remove-without-Defeat consequence.
