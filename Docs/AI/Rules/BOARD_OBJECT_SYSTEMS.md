## Board and object rule systems

Printed rulebook page numbers are used below.

| System | Primary source | Current status | Required verification notes |
| --- | --- | --- | --- |
| Targeting, presence checks, geometry, immunity, and object type | Rulebook pp.9-10, 13, 17-19 plus verified roster cards | Targeting, presence, shared immunity, effective type, Radius, straight-line, and the bounded roster target/set/pair geometry implemented; broader zone/general query language remains specified | `ImmunityQuery` combines exact-activity declarations with standing p.13 Heavy immunity and is consulted at candidate and final-mutation time by Attack, direct Move, Object Push, Place, and Swap. It uses effective-minion accompaniment while the protected subject remains an intrinsic Heavy; milestone 8.19b's typed DirectMove/Swap override can bypass that standing answer only, while an independently declared immunity still wins. Presence deliberately consults no immunity. `EffectiveUnitKindQuery` applies p.17 replacement and `IntrinsicKindQuery` preserves explicit miniature rules. `RadiusQuery` asks targeting and presence separately over p.9's inclusive disk with no line of sight. The 8.19b handlers add canonical single/set/pair choices; behind-target, charge-endpoint and through-target line bindings; former target space; history; count/presence; pre-consequence adjacency; and adjacent terrain. Charge and through are pure selectors whose later direct-Move node owns mutation, and every candidate is rederived on answer/restore under the exact chooser. |
| Obstacles and occupancy | Rulebook pp.18-19 | Generic, minion, token, terrain-overlay, permission, and effective-characteristic consumers implemented | One shared index enforces one obstacle per space; token properties, actor-qualified restrictions, Move-Through permission, terrain presence, and configured entry/exit consumers use typed queries without changing occupancy identity. |
| Object Push | Rulebook p.18 plus cards | Implemented through adjacency- and target-named declarations and used by verified configured heroes | Straight-away geometry, transit/endpoint separation, optional distance, batch commit, typed immunity, and zero-space results share one implementation. Object Push is not Lane Push, Movement, or Place. |
| Place | Rulebook p.18 plus cards | Implemented as one shared operation and used by verified configured heroes | Immutable policy declares board/supply source, piece kind, destination, chooser, and no-destination behavior; configured cards, token placement, and correction fallback reuse it. |
| Spawn and Respawn | Rulebook pp.7-8, 19 plus cards | Unit Spawn, Hero Respawn, Lane-Push minion respawn, and Defeat integration implemented | Spawn retains supply, own-point, token-clearance, and obstacle checks. Hero Respawn offers legal own-Throne spawns or nearest fallback plus resolve-without-action; Lane Push uses the resumable transition and blocked-spawn Place choice. |
| Board-object Swap and Replace | Rulebook p.19 plus cards | Implemented and used by verified configured heroes | Swap is one transaction; Replace commits a typed substitution without leaving the space empty. Both stay distinct from action replacement and card upgrade. |
| Remove, Defeat, prevention, and Clear | Rulebook pp.8, 12-14, 18-19 plus cards | Minion/hero consequences, Clear, general Remove, and verified card-price prevention implemented | Remove has no reward; Defeat stages reward and a preventable removal with separate facts. Brogan's Bolster answers the shared removal decision from both entry altitudes. Clear remains a distinct replacement. Qualifying successful removals record p.8's Lane-Push cause. |
| Token instances, supply, properties, and interactions | Rulebook pp.8, 18-19 plus cards | Instance, supply, occupancy, placement/reclamation, properties, Clear, Spawn, displacement, Swap, Replace, Remove, and cleanup implemented; configured roster owns no token supply | Stable token identity and trusted definitions drive finite supply, occupancy, continuous properties, cleanup, and all typed board operations. A second definition preserves p.19 Replace semantics. |
| Marker attachments, properties, and return | Rulebook pp.8, 13, 18-19 plus cards | Attachment, finite supply, Poison properties, projection, and both return checkpoints implemented for Tigerclaw | Attachments record owner, holder, source and return condition without board coordinates. Poisoned Dagger/Dart give a configured live marker; p.8 and p.13 return the exact applicable attachments. |
| Minions outside Battle Zone | Rulebook p.18 | Correction authority, immutable projection, board-first answer surface, snapshot, replay, and Undo implemented | Applies only to intrinsic minions; corrects after the action by shortest empty path or nearest Battle-Zone Place, with Tie-Breaker ordering and authority-owned candidates. |
