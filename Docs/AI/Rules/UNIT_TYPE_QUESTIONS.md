## Unit-type question ledger

Milestone 6.8g. Every implemented rule that names a unit type declares here whether it asks the intrinsic question (what miniature is this) or the effective question (what does this object currently count as), with the clause that settles it. Printed rulebook page numbers. The governing doctrine is p.17: "If an object counts as an object of a different type, all rules and qualities of that object are replaced by the rules and qualities of the object type(s) it now counts as" - a maximal replacement whose only stated exception is p.18's displaced-minion correction, which names minion miniatures explicitly and exempts "objects that count as minions". A rule whose clause does not settle the question for a counts-as object is recorded as an open rules question below rather than answered by implementation convenience.

| Rule | Code site | Question asked | Settling clause |
| --- | --- | --- | --- |
| Attack target assembly | `AttackTargetQuery.FindLegalEnemyTargets` / `FindLegalEnemyHeroes` | No type question | p.13 "You may attack enemy heroes and minions" names the union of both unit types; enumerating the hero and minion registers is unit enumeration, and a `Counts As` declaration cannot move an object into or out of "heroes and minions" |
| Declared activity immunity | `ImmunityQuery.IsImmune` | No kind read | One exact-activity declaration lookup with the p.18 self exception; Attack, direct Move, Object Push, and Place share it at offer and mutation boundaries |
| Heavy immunity - immune subject | `ImmunityQuery.IsImmuneHeavy` | Intrinsic subtype | p.13 "the heavy minion is Immune" names the Heavy miniature itself; a generic counts-as minion has no Heavy subtype |
| Heavy immunity - accompaniment | `ImmunityQuery.HasStandingHeavyImmunity` over its own Battle-Zone membership scan | **Effective** | p.13's friendly non-Heavy minion presence is a bare membership question, so p.17 replacement applies and a counts-as-minion hero accompanies the Heavy |
| Minion Battle membership, selection, removal | `MinionBattleRules.Plan`, `PendingMinionBattleChoice`, `RoundResolutionAuthority.CompleteMinionBattle` | **Effective** membership; intrinsic Heavy subtype | p.8 counts/removes minions and p.17 replaces type rules. The user-approved consequence interpretation removes a counts-as hero without Defeat/reward/Life and routes it to p.7 Hero Respawn. The 2026-08-23 decision at [ledger question 7](../RULES_LEDGER.md#open-source-and-rules-questions) confines that interpretation to this project's own synthetic object: a *published* hero who counts as a minion states the consequence on his own card, as Brogan's `One Man Army` does, so no general fallback is built and each such card is read instead |
| Minion Defense modifiers | `StandardMinionProfileCatalog.Rulebook` read by `DefenseValueQuery.CalculateMinionContributions` | Intrinsic subtype | p.14 assigns every modifier by subtype - adjacent friendly/enemy melee or heavy, enemy ranged in radius 2 - and a generic `Counts As` minion declaration carries no subtype, so no p.14 branch can apply to it; the effective vocabulary deliberately has no subtypes (6.8g non-goal) |
| Minion defeat reward | `StandardMinionProfileCatalog.Rulebook` read by `AttackDefenseCardActionStrategyBackend.ResolveMinionTarget` | Intrinsic, recorded as open question 8 | p.13 prices defeats by intrinsic identity - melee/ranged 2 coins, heavy 4, heroes by level - and no clause prices a defeated object that merely counts as a minion |
| Displaced-minion correction | Implemented general core authority at 6.4a with player-facing choices at 6.4b | Intrinsic by explicit citation | p.18: "This is only relevant for minions represented by minion miniatures; objects that count as minions are unaffected!" The subject set is the board's miniature occupancy itself and the derivation takes no modification set, so no counts-as declaration can reach it. |
| Fast-Travel enemy conditions | `FastTravelActionQuery.ContainsEnemy` | No type question | p.11 requires "no enemy heroes or minions" in the origin and destination Zones - the type-insensitive union of all units |
| Presence | `UnitPresenceQuery.FindUnitsWithin` / `IsPresentWithin` / `FindUnitsInZone` | Effective | p.17 replacement doctrine plus p.18's immune-unit presence note already cited in the query's documentation; presence counts what an object currently counts as |
