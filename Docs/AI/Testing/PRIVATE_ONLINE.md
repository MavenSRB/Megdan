## Shared command forms

Unity-free focused fixtures use:

```powershell
dotnet test Tools/DotnetTests/GuardsDigital.DotnetTests.csproj --no-restore --filter "FullyQualifiedName~<fixture>"
```

Unity focused fixtures use `tmp/unity-validation-request.json` with the exact `platform` and ordered `filters` selected below, milestone-specific result/log paths beneath `tmp`, followed by the fixed launcher. Compatible filters on one platform and batch-mode boundary use one grouped request; Edit/Play, batch/non-batch, and different process-global setup remain separate serial invocations:

```powershell
& 'C:\Projects\Guards Digital\Guards 0.1\Tools\Invoke-UnityValidation.ps1'
```

The exact local multi-process runner selected for the disposable player build is `Tools/Invoke-PrivateOnlineRehearsal.ps1`. Milestone 8.31 creates it with a loopback smoke mode; 8.35c extends the same entry point to `-Topology SixClient -FaultPlan Full`. `-Topology LoopbackSmoke` starts one dedicated seatless host and six client processes and must never bind a non-loopback interface. It must start hidden processes, use only workspace outputs, record exact build/protocol/schema/map/content identities, bound execution, stop only its owned PIDs, and fail on missing/non-green convergence, privacy, or process-exit evidence.

Each topology is paired with exactly one fault plan and the runner refuses any other pairing: `LoopbackSmoke` runs only with `None`, and `SixClient` only with `Full`, because the 8.35c row below names one six-client combination and a weaker run must not be mistaken for that gate. `SixClient` runs two cohorts against one build - a full match cohort and a terminal host-loss cohort - and the host-loss cohort's own host termination is the single deliberate external process kill in either topology; every other process must exit on its own. The invitation endpoint and session key reach each player through that child process's environment block rather than its command line, and the privacy review additionally fails on any log carrying the generated key.

## Fault-plan constants

The deterministic local fault injector operates above the socket adapter and below the protocol codec so it is transport-independent and replayable. `Full` means: drop one outbound projection, delay one within the bounded window, deliver two duplicates, reorder two messages, replay one completed submission, submit stale/current/future projection versions, use an unknown kind/discriminator, truncate a frame, declare a mismatched length, exceed every configured size limit by one byte, forge every stable identity field, disconnect/reconnect each pending family at the five required cut points, expire reconnect eligibility, and terminate the host. Each case records its fixed seed and smallest message prefix.

No fixture may log another seat's owner-private fields to prove absence. Privacy checks deserialize each captured client byte stream and inspect the typed field inventory; diagnostics checks compare against an explicit allow-list.
