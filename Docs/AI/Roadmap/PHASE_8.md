### [x] 8.35v END TURN is omnipresent during the acting seat's own turn and one press cancels and ends it

THIRD amendment, REVISED SEMANTICS (2026-09-04): "end turn button should be present the whole time on players action turn, even if he has attack selection on. If you click end turn, just cancel selections and end the turn" - superseding 8.35g's shipped double-press with one: an explicit END TURN press discards the seat's own open, not-yet-committed selection AND performs whatever legal completion it implies (stop, decline, or Hold) AND releases the turn, all in the same press. "Undo is for that, end turn is for ending the turn."

Observable outcome: during the acting seat's own turn, END TURN is always drawn - mid-movement, with an Attack target open, with an undeclined optional branch standing, or with nothing started at all. One press composes whatever the state calls for and hands the turn on in the same accepted-command sequence: a movement Stop, an effect choice's own Decline or Stop, or p.12's Hold, each immediately followed by the release once it stands. Where a printed rule leaves the step no legal decline (a Movement below its required minimum, an effect choice with real candidates and neither a Decline nor a Stop of its own), or the resolution has moved past anything this seat can answer or cancel (an Attack target already accepted and awaiting its defense - milestone 8.35f/8.35p's own wall), END TURN is drawn DISABLED rather than hidden, its cursor tooltip naming the reason from the SIXTH amendment's fixed vocabulary (`MANDATORY STEP` / `ANOTHER SEAT'S DECISION STANDS`).

Design:

- `MatchFeaturePresenters.CreateEndTurnInvocation` gains a fourth branch, checked ahead of its existing Stop/Release branches: `PendingEffectChoice.DeclineInvocation` - the amendment's own named "undeclined optional branch" case, missed in the first pass of this design and caught by re-reading the amendment's exact wording. It reads the SAME pre-built invocation the contextual region's own ACCEPT/DECLINE banners answer, never composing a new one.
- `RoundActionViewModel` carries two new, mutually exclusive facts alongside `EndTurnInvocation` (the constructor throws if more than one is set): `EndTurnCancelsOpenAttack` (true exactly when `PendingAttackTargetChoice` stands open and the seat's own 8.35f/8.35p bounded rewind, `IsSeatUndoAvailable`, is genuinely legal - the wall has not risen) and `EndTurnUnavailableReason` (the disabled tooltip text, gated on a new `IsViewerTheActingHero` helper comparing `SelectedActor.ActorId` against the viewer's own hero).
- `RoundActionPresenter.SubmitEndTurn()` is the one press's whole composition: while a Clear selection (6.3a) is open it is cancelled first (`CancelClear`, a pure presentation reset - nothing was ever submitted for an unconfirmed Clear, so there is nothing to rewind), then whatever `EndTurnInvocation`/`EndTurnCancelsOpenAttack` next offers is composed - a direct completion via `Execute`, or the seat's own `SubmitSeatUndo()` - bounded at 8 iterations. The whole loop is bounded to the ONE actor the press is for: `pressActorId` is read once, and every iteration verifies the projection still concerns that hero (still resolving it, or still awaiting ITS OWN release) before composing anything else, so a Director client - which sees every actor's own END TURN in turn, unlike a seat - can never carry one press past its own release into a second player's turn. `ConfiguredMatchSceneRuntime.SubmitEndTurn()` forwards to it, so every existing caller (every Play Mode journey filler) keeps its method name and signature. The drawn control raises a new parameterless `EndTurnRequested` event (mirroring 8.35f's `SeatUndoRequested`) instead of the generic `ForwardInvocation`/`InvocationSubmitted` path; `RoundActionPresenter.Submit` separately gained its own one-hop auto-chain-to-release for direct callers (a raw `ForwardInvocation`/`Submit` of the drawn invocation, which several existing Edit Mode cases and the live HUD's simple states still exercise).
- `UiToolkitMatchHudViews.RebuildEndTurn` no longer lets `HasExclusiveDecision` hide the control - that predicate used to suppress END TURN during exactly the mandatory-step and another-seat's-decision states the new disabled reason now names, which is precisely what the amendment asked fixed. The disabled state draws the identical `PewterBanner` shape, greyed via `HudElements.MarkUnavailable` (8.29d's own precedent), tooltip set to the reason.
- Three real defects caught by validation, not by review, and fixed before shipping:
  1. **Scoping.** The first draft of the disabled-reason check gated only on `IsTurnActive && SelectedActor.IsDefined` - both PUBLIC, unscoped facts (every viewer's board marks the same acting piece, milestone 8.35n) - so it read true for every seat while anyone's turn was active: a DEFENDER's own screen would have shown a disabled END TURN reading "ANOTHER SEAT'S DECISION STANDS" during their own Defense answer, and a pure spectator would have seen the same for no reason at all. The identical trap `AwaitedInputQuery` already names for the top-bar predicate. Fixed with `IsViewerTheActingHero`, which required a third public `RoundActionPresenter.CreateViewModel(projection, homeHeroId)` overload, because the two existing ones both default it to the Director sentinel.
  2. **Clear ordering.** `CreateEndTurnInvocation` does not read `ClearSelection` (6.3a) at all, so with nothing else pending it already projected the ordinary Hold alongside a still-open, unconfirmed board selection - submitting Hold first would have left the Clear orphaned rather than cancelled. Caught by the 8.35u worker's own Edit Mode run against this milestone's uncommitted work (`PromptReachabilityConformanceTests.TheOpenClearSelection_IsAnsweredOnTheBoardAndKeepsNoCandidateControl`, which now also expects the omnipresent control's own harmless presence). Fixed by checking Clear first in `SubmitEndTurn`'s loop.
  3. **Actor crossing.** The first working draft of `SubmitEndTurn` kept composing off `EndTurnInvocation` alone; for a Director client (which answers for everybody) this correctly chained a Hold into its own auto-released Stop/Decline, but the very next loop iteration then found the NEXT actor's own untouched-card Hold and submitted that too, silently spending a second player's turn inside a press that was only ever about the first - caught by `RoundPresenter_SubmitEndTurnCollapsesAMovementStopAndReleaseIntoOnePlayerPress` failing deterministically (`Expected: StopMovement But was: PerformHold`) in an otherwise-green complete Edit Mode run. Fixed with the `pressActorId` boundary described above.
- One further conformance fix, not a production defect: `PendingDecisionContractConformanceTests`'s own Effect-family command aggregation counted the Decline invocation twice (once via `EffectChoices`, once via `EndTurnInvocation`, the identical object reference) once finding #1 above shipped; its `SurfaceCommands` helper now folds END TURN's command in only when it is not already one of the ordinary controls.

Acceptance checks:

- One press from every state reaches the release (or completes the turn) in the same accepted sequence: mid-movement (`RoundPresenter_SubmitEndTurnCollapsesAMovementStopAndReleaseIntoOnePlayerPress`), untouched card (`RoundPresenter_SubmitEndTurnCollapsesHoldAndReleaseIntoOnePlayerPress`), an open Attack target selection pre-target over a real seat client (`RoundPresenter_EndTurnCancelsAnOpenAttackTargetSelectionAndReleasesInOnePress`, driven from the official six-seat state via `OwnerScopedProjectionTests.DriveThroughSeats` - `IsSeatUndoAvailable` is host-tracked from the turn's own beginning and cannot be proved by wrapping an already-mid-turn session), an open Clear selection (`RoundPresenter_EndTurnCancelsAnOpenClearSelectionFirst`), and a naturally-completed resolution already standing in the release pause (`RoundPresenter_SubmitEndTurnReleasesANaturallyCompletedTurnInOnePress`).
- Discard-does-not-commit: cancelling an open Attack target selection never answers it - the recorded stream never contains a `ChooseAttackTarget` for it; cancelling an open Clear never contains a `PerformClear` (same two cases as above).
- Disabled-with-reason: a Movement below its required minimum and a mandatory effect-choice mode both draw `MandatoryStep` (`RoundPresenter_EndTurnIsDisabledWithMandatoryStepWhenMovementCannotStopYet`, `RoundPresenter_EndTurnIsDisabledWithMandatoryStepForAMandatoryEffectChoice`); a disabled control refuses `SubmitEndTurn()` rather than silently doing nothing wrong.
- The wall: a press after `ChooseAttackTarget` is accepted (mid-attack, awaiting defense) is disabled with `AnotherSeatDeciding`, never composing a cancel (`RoundPresenter_EndTurnIsDisabledAsAnotherSeatsDecisionMidAttackAfterTargetIsChosen`).
- A non-owner seat draws no END TURN control at all - enabled, cancelling, or disabled - extending `SeatScopedMatchHudTests.EndTurnStandsAloneForTheSeatThatMayEndTheTurnAndIsDrawnForNobodyElse`, which was itself corrected to thread each seat's own `homeHeroId` (finding #1) rather than the Director-shaped overload it had been calling.
- Complete Edit Mode: 2,510/2,510 (up from the 2,502 baseline this milestone's own eight new cases and one new fixture file account for). Complete Play Mode: 278/278. Both reached green only after the three defects above were found and fixed by the runs themselves - each surfaced deterministically, in isolation, and stayed fixed on re-run, which is this milestone's pre-fix/post-fix pairing in the shape validation actually produced it in rather than a separate synthetic revert.

### [x] 8.35w Bound the projection's completed-round history to a retained window

Corrective, pre-build, from the live host crash recorded in `tmp/private-online-solo-host.log`. `SeatProjection.CompletedRounds` carried the entire match's round history, in full, to every seat on every projection push, and its source - `RoundResolutionAuthority`'s own list - is append-only. The failure is terminal for the whole table rather than a dropped frame: `SendProjectionTo` has already advanced the send sequence when the throw lands, so every client reads a Gap, the resync it asks for is served down the same throwing path, and the exception unwinds `PublishProjections` so no later connection is served either. The match stalls for all six players with nothing on any screen and no recovery.

Observable outcome: a match that runs to its own ending, past forty completed rounds, keeps every seat projection frame inside the protocol's payload bound, and a seat that disconnects and returns mid-match is served the same bounded window as one that never left. Each seat reviews the four most recent completed rounds; the rules, the restore state and the authoritative snapshot still hold every round the match played.

Design:

- The bound is `MatchSessionProjection.RetainedCompletedRounds`, applied at the READ MODEL rather than in the codec, so `MatchSessionProjection`, the `SeatProjection` derived from it and the `NetworkMatchClient` that decodes it all report the same window. A cap inside `WriteCompletedRounds` would have made the encoded frame disagree with the projection it was encoded from, which is the one thing convergence is asserted on.
- `MaxPayloadBytes` is deliberately NOT raised. Its own doc comment states its purpose - a declared length cannot buy an allocation - so it is a defensive read-side cap applying to every message kind from every peer; raising it would weaken that for all of them and leave the term unbounded, producing the same freeze at a higher round number. A growth term with no limit is not fixed by a larger limit.
- `RoundResolutionAuthority` is deliberately not windowed, and now says so at its own `CompletedRounds`. This is a bound on what a seat is SHOWN, not a loss of history.
- Four is measured rather than chosen: the frame decomposes into 35,997 bytes that do not grow with match length plus 1,108 bytes per retained round, so a window of four saturates it at 40,431 bytes - 61.7% of the 65,536-byte ceiling and 77.2% of the frame fixture's deliberate-resize guard, leaving 11,964 bytes against the 2,835 bytes the rest of the frame grew across all of 8.33 to 8.35r. Four is also the measured reach of the 8.35r match-log window this same projection already carries, so the two history surfaces a seat reviews cover the same span rather than one of them silently deciding what recent means for both.
- No wire version and no schema move: `PrivateSessionProtocol.cs` and `Core/Snapshots/` are absent from the diff, the field is already a count followed by that many records, and the snapshot captures the authority's own full list.

Acceptance checks:

- `PrivateOnlineEventChannelTests.TheProjectionFrame_StaysInsideItsBound_ThroughAMatchThatRunsToItsOwnEnding` drives until the match ends itself and refuses to pass unless it saw an ending past forty completed rounds, building the frame through the real codec so an over-long frame fails as the host's own exception rather than as a number. ### [x] 8.35z4 Fix the four defects the first live internet playtest found

Corrective, live-defect-driven, and the first milestone whose defect list was written by a real six-human internet session rather than by a rehearsal - though its own evidence, as always, is local. Territory: Presentation/Match only - no Core, Application or Network file is touched. Design:

- **The keystone.** `RoundActionPresenter.FormatStatus`'s two team-agreement branches handed an EMPTY owed-set to `NarrationLabels.WaitingOn`, which refuses it by design. An agreement every participant has already answered is an ordinary transient state that every seat refreshes through, so from the first one the panel threw on every refresh. Milestone 8.35h's panel isolation then contained the throw to that one panel - which is what turned a crash into something quieter and worse, because everything else riding the same refresh, the kinetic cue emission included, was starved. - **The identity.** A networked client cannot know its hero at composition time; the lobby grants the seat afterwards. `ConfiguredMatchSceneRuntime` composed all three seat-scoped presenters with `Seat?.HeroId ?? default` and repaired exactly one, the other two holding their identity in `readonly` fields. The undefined hero is not a neutral blank - it is the DIRECTOR's identity, and the Director owns every decision at once, so every "is this mine?" predicate read an unrepaired seat as "yes". New `ISeatScopedPresenter`, both fields made mutable with a validating `SetHomeHero` that drops the per-projection cache, and one `BindHomeHero` fan-out over `SeatScopedPresenters` that refuses loudly rather than leaving a half-bound HUD.
- **The one press.** The compose loop in `SubmitEndTurn` re-reads `session.Projection` after every step, which is exact against a synchronous client and wrong against the wire: `NetworkMatchClient.Submit` returns as soon as the command is SENT, handing back the pre-command projection, and `PrivateSessionClient` refuses every further submission while `IsWaitingForHost`. The press is now remembered and resumed - armed when the input gate is closed and the state still concerns the press's own actor, continued from `Refresh`, which the online frame loop already calls - bounded to that one actor and to `MaxEndTurnResumes` resumptions so it can neither spend a second player's turn nor become permanent. **That bound was unreachable as first written**, and the six-client rehearsal is what found it: `ArmOrClearEndTurnContinuation` reset the counter unconditionally, and every resumption re-arms through it, so the comparison could never be met and a press whose submissions kept being refused resumed on every frame forever - live, one seat spent 17,486 refused submissions at a single authoritative version while the table stood still. The budget now belongs to the press rather than to each resumption of it: only a fresh press resets it.
- **The pace.** `Begin` started the floating figure at `Elapsed = 0`, the same instant as its cue, but a lunge's `Strike` curve does not peak until 34% in, so the number preceded its own cause by about 95 ms. The figure now begins one impact-delay behind the clock, derived from the curve's own peak rather than a literal, and `FloatingNumberSeconds` moves 0.90 -> 1.5.

Acceptance checks:

- The round panel survives every projection of a real seeded six-seat match for every viewer, the Director included, with the panel failure sink empty - the guard that catches this whole class rather than the one branch that failed.
- Every phase that can build a waiting-on line is staged with an empty owed-set, and the `WaitingOn` vocabulary still refuses to name nobody.
