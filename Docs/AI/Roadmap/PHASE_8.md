### [x] 8.35q Fill empty seats with spawned test drivers for solo playtesting

THIRTEENTH amendment: "I find it really hard to test running 6 clients at once. Can you make AI play the game or something so i just play with one client only?" Answer: expose the existing rehearsal/SixClient machinery's real-lobby, real-HUD, offers-intersected-with-AuthorizedCommands pattern as a shipped, user-facing practice affordance - explicitly NOT an AI opponent (durable non-goal unchanged).

Observable outcome: the host's lobby (`Tools/PlaytestLaunchers/HOST - Start Server.bat`, the interactive lobby a real solo player actually runs, per 8.35o's own finding) offers FILL WITH TEST DRIVERS whenever a seat is still Open and the match has not started. Pressing it spawns one real keyed client process per Open seat - the same running executable, re-launched with a distinct log path - each of which joins the real lobby, claims its seat, and answers whatever it is offered (commitments, defenses, agreements, leveling, releases) with a random legal choice at a human-followable pace (2 s default, overridable). Every spawned process is the host's own OS child, killed when its session ends.

Design:

- Host affordance is a lobby control only (`PrivateLobbyControl.FillWithTestDrivers`), not a launcher flag - the raw `-guardsPrivateHost` CLI role is CI/rehearsal-only and no real tester ever touches it.
- Reuses `PrivateOnlineRehearsalDriver.AuthorizedProjectedCommands` (bumped `internal`) directly rather than duplicating it; the new, much simpler `PrivateSeatDriver` (new file) carries the shipped behavior, deliberately kept separate from the 1184-line CI-only rehearsal driver rather than growing it. New CLI vocabulary (`-guardsTestDriver`, `-guardsTestDriverSeat`, optional think-seconds/seed), endpoint/key via env vars only - the same command-line-secrecy rule the rehearsal driver already follows.
- Spawning goes through `ITestDriverProcessLauncher`, a small seam so the spawning DECISION is Edit-Mode-testable without ever starting a real process; `RealTestDriverProcessLauncher` is production. Labeling (`PrivateLobbySeatRow.IsTestDriverSeat`) is deliberately host-screen-only, sourced from the host's own local spawn record rather than the roster - putting it on the wire would be the protocol change the amendment says isn't expected.
- No new session-layer member, no protocol change - verified by grep, and by the regression completing under the unmoved wire version.

Acceptance checks:

- `PrivateLobbyModel.ForHost` offers `FillWithTestDrivers` exactly while a seat is Open and the match has not started, and labels a host-spawned seat's own row `IsTestDriverSeat` from the caller-supplied set alone, never the roster.
- `PrivateLobbyPresenter.Press(FillWithTestDrivers, ...)` raises `FillWithTestDriversRequested` without touching any session itself - spawning stays the one thing only the driver may know how to do.
- `PrivateSeatDriverOptions.TryParse` accepts a well-formed line and refuses a missing seat, a missing lobby flag, a non-loopback address, and an empty session key, each with its own named reason.
- Regression: a solo cohort in `Invoke-PrivateOnlineRehearsal.ps1 -Topology Solo -FaultPlan None` - one scripted "human" seat plus the host's own real FILL control filling the other five - completes a full six-player match to one converged outcome from only two launched processes, and no spawned test-driver process outlives the host session that spawned it.

Non-goals: No AI opponent, strategy, or difficulty - every legal answer is equally likely by design, a durable property. No wire/protocol change. No in-process second driving path - every seat is an ordinary keyed process. No change to the CI-only rehearsal driver's own scripted cohorts beyond the new `Solo` mode that drives this regression.

### [x] 8.35r Publish the seat-public match log and who the table is waiting on

TENTH amendment: "Make a log ... Its to tell players what happened previously in the game. But player facing: Moves, Attacks, Defenses, Skills used." Undo, replay and resync redraw it for free because `MatchSession.Undo` reconstructs from the retained command prefix.
- Selection is exactly `tmp/8-35d-8-35e-multiplayer-corrections/worker-b/EVENT_LOG_CONTRACT.md` §1, typed as `MatchLogEntryKind` so no surface parses diagnostic prose, with event names built from the rule-event enum members via `nameof` so a renamed kind is a compile error rather than a line that silently stops being selected.
- The seat filter is an IDENTITY, and that is the privacy proof: §1 admits only events the whole table can already see, so every seat's log equals the Director's and there is nothing to redact.
- The log rides inside the seat projection message beside that seat's record - not in the record, which has 2,173 B of headroom under the sweep's own guard, and not in its own message kind, which consumed a gameplay sequence and absorbed the gaps a dropped projection must leave for client recovery.
- `DecisionOwner` joins `IMatchReadModel` and moves no bytes: the seat record has carried it since 8.35's wire slice and only the read-model contract lacked it. Who is awaited is table-public; what they may choose stays owner-private on `DecisionContract`.
- `UndoMarker` is a published read-model fact rather than a synthetic log entry, because an undo records no command and no event and a minted entry would have to be stored.

### [x] 8.35w Bound the projection's completed-round history to a retained window

Corrective, pre-build, from the live host crash recorded in `tmp/private-online-solo-host.log`. `SeatProjection.CompletedRounds` carried the entire match's round history, in full, to every seat on every projection push, and its source - `RoundResolutionAuthority`'s own list - is append-only. It was the one match-length-linear term in a seat projection, at a measured 1,183 bytes per completed round, so the host walked its own frame into `PrivateSessionProtocol.MaxPayloadBytes` and threw out of `PrivateSessionFrameCodec.EncodeFrame` on its own honest traffic. Measured on the official six-player configuration that lands at 33-34 completed rounds - inside the length ordinary matches reach, with six of ten seeded walks crossing it. The failure is terminal for the whole table rather than a dropped frame: `SendProjectionTo` has already advanced the send sequence when the throw lands, so every client reads a Gap, the resync it asks for is served down the same throwing path, and the exception unwinds `PublishProjections` so no later connection is served either. The match stalls for all six players with nothing on any screen and no recovery.

Observable outcome: a match that runs to its own ending, past forty completed rounds, keeps every seat projection frame inside the protocol's payload bound, and a seat that disconnects and returns mid-match is served the same bounded window as one that never left. Each seat reviews the four most recent completed rounds; the rules, the restore state and the authoritative snapshot still hold every round the match played.

Design:

- The bound is `MatchSessionProjection.RetainedCompletedRounds`, applied at the READ MODEL rather than in the codec, so `MatchSessionProjection`, the `SeatProjection` derived from it and the `NetworkMatchClient` that decodes it all report the same window. A cap inside `WriteCompletedRounds` would have made the encoded frame disagree with the projection it was encoded from, which is the one thing convergence is asserted on.
- `MaxPayloadBytes` is deliberately NOT raised. Its own doc comment states its purpose - a declared length cannot buy an allocation - so it is a defensive read-side cap applying to every message kind from every peer; raising it would weaken that for all of them and leave the term unbounded, producing the same freeze at a higher round number. A growth term with no limit is not fixed by a larger limit.
- `RoundResolutionAuthority` is deliberately not windowed, and now says so at its own `CompletedRounds`. This is a bound on what a seat is SHOWN, not a loss of history.
- Four is measured rather than chosen: the frame decomposes into 35,997 bytes that do not grow with match length plus 1,108 bytes per retained round, so a window of four saturates it at 40,431 bytes - 61.7% of the 65,536-byte ceiling and 77.2% of the frame fixture's deliberate-resize guard, leaving 11,964 bytes against the 2,835 bytes the rest of the frame grew across all of 8.33 to 8.35r. Four is also the measured reach of the 8.35r match-log window this same projection already carries, so the two history surfaces a seat reviews cover the same span rather than one of them silently deciding what recent means for both.
- No wire version and no schema move: `PrivateSessionProtocol.cs` and `Core/Snapshots/` are absent from the diff, the field is already a count followed by that many records, and the snapshot captures the authority's own full list.

### [x] 8.35z4 Fix the four defects the first live internet playtest found

Corrective, live-defect-driven, and the first milestone whose defect list was written by a real six-human internet session rather than by a rehearsal - though its own evidence, as always, is local. Territory: Presentation/Match only - no Core, Application or Network file is touched. Design:

- **The keystone.** `RoundActionPresenter.FormatStatus`'s two team-agreement branches handed an EMPTY owed-set to `NarrationLabels.WaitingOn`, which refuses it by design. An agreement every participant has already answered is an ordinary transient state that every seat refreshes through, so from the first one the panel threw on every refresh. Milestone 8.35h's panel isolation then contained the throw to that one panel - which is what turned a crash into something quieter and worse, because everything else riding the same refresh, the kinetic cue emission included, was starved. Fixed at the CALLER via `FormatAgreementWait`: an empty owed-set is a real state and gets `NarrationLabels.EveryAnswerIn`. `WaitingOn` stays defensive so the next forgetful caller is still caught.
- **The identity.** A networked client cannot know its hero at composition time; the lobby grants the seat afterwards. `ConfiguredMatchSceneRuntime` composed all three seat-scoped presenters with `Seat?.HeroId ?? default` and repaired exactly one, the other two holding their identity in `readonly` fields. The undefined hero is not a neutral blank - it is the DIRECTOR's identity, and the Director owns every decision at once, so every "is this mine?" predicate read an unrepaired seat as "yes". New `ISeatScopedPresenter`, both fields made mutable with a validating `SetHomeHero` that drops the per-projection cache, and one `BindHomeHero` fan-out over `SeatScopedPresenters` that refuses loudly rather than leaving a half-bound HUD.
- **The one press.** The compose loop in `SubmitEndTurn` re-reads `session.Projection` after every step, which is exact against a synchronous client and wrong against the wire: `NetworkMatchClient.Submit` returns as soon as the command is SENT, handing back the pre-command projection, and `PrivateSessionClient` refuses every further submission while `IsWaitingForHost`. The press is now remembered and resumed - armed when the input gate is closed and the state still concerns the press's own actor, continued from `Refresh`, which the online frame loop already calls - bounded to that one actor and to `MaxEndTurnResumes` resumptions so it can neither spend a second player's turn nor become permanent. **That bound was unreachable as first written**, and the six-client rehearsal is what found it: `ArmOrClearEndTurnContinuation` reset the counter unconditionally, and every resumption re-arms through it, so the comparison could never be met and a press whose submissions kept being refused resumed on every frame forever - live, one seat spent 17,486 refused submissions at a single authoritative version while the table stood still. The budget now belongs to the press rather than to each resumption of it: only a fresh press resets it.
- **The pace.** `Begin` started the floating figure at `Elapsed = 0`, the same instant as its cue, but a lunge's `Strike` curve does not peak until 34% in, so the number preceded its own cause by about 95 ms. The figure now begins one impact-delay behind the clock, derived from the curve's own peak rather than a literal, and `FloatingNumberSeconds` moves 0.90 -> 1.5.

Non-goals: no Core, Application or Network change; no wire protocol, snapshot schema or content revision movement; the `!IsDefined` Director branches are deliberately left standing, because they are correct and load-bearing for the Director, whose runtime legitimately passes the undefined hero.
